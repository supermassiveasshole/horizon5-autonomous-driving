## 软件证据

通过 `run_experiment` 验证实际 Torch 训练在模拟积压期间暂停，恢复后 3 次更新所得预测与相同种子的普通训练逐条一致，输入数据字节未变。

故障输入覆盖持续积压、状态陈旧、指标缺失、内存超限、归档错误/异常结束、中途资源压力、停止请求、总预算用尽和工作单元超时。停止时保存调度报告，不发布 `candidate/`；已完成更新数与退出原因可见。

两项 CUDA 准入反例无需开启 CUDA：采集仍运行时不启动 GPU 训练；采集正常结束但设备显存超过预算时仍等待并有界退出。它们证明准入策略，不能证明 CUDA 张量搬移或真实并行性能。

采集新增 last-poll、最后可用图像源时间及 session 绑定字段。图像年龄按实际采样时刻计算，约一秒的状态发布间隔不冒充图像年龄；旧环境缺字段不被默认为健康。

## 独立进程原型

本地 `runs/t38-scheduled-collector-20260930/prototype.json`、`scheduled/schedule.json`、`scheduled/candidate/report.html`、`collection-reviewed.html`。真实启动一个隔离的 **合成采集进程**，通过系统进程身份验证其运行，并读取当前学习进程的真实 Windows 内存计数；没有游戏、截图、UDP/XInput 或虚拟控制。

- 数据来源为 64×36 常色合成 RGB；后台采集使用 2×1 合成帧。尺寸不同是因为本原型验证进程调度，后台数据不混入当前模型快照。
- 等待采集初始化/图像历史建立，累计等待约 1.4 秒，随后完成 3 次 CPU 更新和冻结预测回放。
- 调度观察到后台采集行数从 0 增至 223；训练结束时采集进程仍运行，数据快照字节不变。
- 人工界面和驾驶均未介入。脚本随后发送正常停止请求；最终 250 行全部写入、13 块、零丢弃，进程退出，封存复核无错误。
- 原型最长已完成工作单元约 0.600 秒；这是初始化/训练/预测单元的 CPU 诊断，**不是控制周期或 GPU 抢占时限**。
