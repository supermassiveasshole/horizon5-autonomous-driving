# T32 / #34：DXGI 数值采集软件验证

日期：2026-09-30。本轮未启动 FH5 或 Steam、未连接虚拟手柄、未发送驾驶动作。基础切片已实现，#34 仍开放；动态游戏、MSS 同场景比较及浏览器交互尚未验收。用法与剩余范围见 [DXGI 采集](../dxgi-capture.md)。

## 已实现并验证

- `run_experiment(CaptureReplay/CaptureRun)` 使用同一有界状态机；一个待处理槽、独立预处理 worker、不取消正在处理的帧，数值历史不可变。
- 原生帧信息与像素来自同一次 DXGI 获取；单调时间由整数 QPC 差值映射。零呈现、鼠标更新时间回退、重复旧时间不算新画面。
- 选帧遵循当时已经完成的历史，保存真实 Δt/age；窗口、布局、失焦和访问错误切开 epoch。失败最多三次恢复，停机记录 worker 与 SDK 资源结果。
- 图像存档在独立有界队列中完成，实时路径不生成或读取 JPEG。CLI 默认只校验配置，显式 `--live` 才被动采集。
- 回放与实时共享预处理频率规则。审查发现的回放忽略频率问题已修复：七个间隔 16 ms 的源帧、1 ms 处理耗时、30 Hz 预处理，只完成四帧并覆盖三次待处理项，最终选择 f3/f5/f7。
- 中断和观测异常保留完整结果及资源释放记录，CLI 不把异常退出当作成功。

原生 SDK 软件测试在实验入口注入独立构造的 48 字节 Win32 帧信息、原始 BGRA 与外部 DXcam 边界，验证匹配、鼠标更新排除、裁剪及释放；这不替代真实图像获取。

## 本机证据及限制

`runs/t34-no-game-20260930/`：0.5 秒显式只读探测，31 次 `target_unavailable`、零帧、资源全部释放，预期非零退出码。未创建截图源，也没有截取其他应用。这些调用耗时仅表示窗口可用性检查，不能称作 DXGI 截图性能。

另做仅创建和释放 SDK 资源的预检，**没有调用 `grab` 或 `AcquireNextFrame`，没有获取像素**：

- NVIDIA GeForce RTX 4090，adapter 0 / output 0，DISPLAY1 的物理区域 3840×2160，未旋转。
- 原生 frame info 为 48 字节，QPC 频率 10,000,000 Hz；本次最窄校准不确定性 300 ns。
- 会话释放成功；结果保存在忽略目录 `.scratch/night-20260930/dxgi-resource-preflight.json`。

该预检仅证明锁定 SDK 的构造、接点与释放可用。桌面尺寸不能证明实际 FH5 客户区、内部渲染、HDR、游戏帧时间或 4K 采集预算。

`runs/t34-software-20260930/` 为六张合成图的确定性回放：150 ms 处理、200/0 ms 历史，四帧处理、一次覆盖，选出 f3/f5。耗时明确为 simulated，不是性能测量。
