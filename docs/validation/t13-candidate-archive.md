# T13：完整候选归档与恢复验证

日期：2026-10-01。范围为 #14 中的候选保留及继续学习，不包含可靠默认版本激活、持久选择历史或实机驾驶验收。公共入口与使用方法见[候选归档](../candidate-archive.md)。

## 行为与边界

- `CandidateArchive` 和 `CandidateRestore` 通过 `run_experiment` / CLI 保存并恢复 SAC v2/v3/v4 的完整依赖，不只保存推理权重。
- 原 `policy.json`、权重、历史、模仿审核、数值经验及教师逐字节保留；落选候选可在新目录继续训练，原默认版本不变。
- 在私有副本中核验模型、经验、历史、优化器、温度及 RNG，比较实际恢复后的完整学习状态摘要。不增加训练阶段，也不预留一个无用后继阶段的历史容量。
- 目标不覆盖；损坏或缺失依赖在发布前拒绝。写盘故障不发布可加载的模型清单，也不把不完整目录标成完成。

## 可复现原型

保留最终复审版本的运行目录：`runs/t13-candidate-archive-20261001-reviewed/`，总核对结果为 `verification.json`。

输入为上一切片实际 CPU SAC 训练留下的 `runs/t10-imitation-20261001/continued/`：累计 35 步，临时模仿已退出，含两份冻结开发评估审核。原始候选及权重未修改。

在独立 Python 进程中执行归档、恢复、继续 5 步训练，并从原候选独立继续相同步数作为对照。两者均累计 40 步，预测和完整学习状态摘要一致，教师调用为零、两份审核仍在，原策略清单字节保持不变。

这是真实 CPU 算法执行配合明确标记的合成经验；没有启动 FH5/Steam、原生捕获或输入设备，不能解释为车辆驾驶能力验证。

## 测试与复审

公共入口回归覆盖原目录移走后续训等价、CLI 往返、v2/v3/v4 训练阶段、依赖损坏、错误摘要、目标冲突、文件写入失败和容量边界。

初次复审发现归档核验调用零步续训，仍会生成后继阶段；现有候选合法但历史容量已满时被误拒绝。归档与恢复两个反例均先失败，再由只读完整性核验修复。Standards 提示的重复发布循环也已合并。

最终专项、全量回归及复审结果在收敛后补充；当前不据此关闭 #14。后续继续实现持久版本选择历史和回退，实际自动晋升仍需独立驾驶证据。
