# T14 / #15：保留失败的有限重采样

日期：2026-10-01。隔离分支 `codex/learning-sampling-retry`，基于资源监测分支 `3217989`。#15 保持开放；未启动 FH5、Steam、原生捕获或控制器。

## 本轮行为

可选 `sampling_retry.max_retries` 限 0–3，按每轮累计，显式接续不刷新额度。已封存、资源释放明确、零更新且无候选输出的失败才能开启新尝试；失败目录和摘要、原件及外部审阅依赖保留。用户停止不会自行重试，之后显式接续可在同一额度内继续。正常候选一旦训练完成，继续进入冻结评估，不因前次失败重复更新。

这不恢复强杀后的未封存阶段，不重新采纳部分写出的候选，不重跑已经失败的评估。当前仅支持已有合成学习入口。

## 已执行证据

公开 `run_experiment` / `LearningContinue` 入口使用实际保留 learner 和独立可写版本库副本。发送失败、停止文件、部分写出目录及释放失败由外部环境/文件系统注入，不替换网络、训练或验证结果；下列原型未启动新训练。

| 场景 | 结果 | 本机原件 |
|---|---|---|
| 连续采样发送失败，额外预算 1 次 | 两个独立目录和接口身份均保留失败，停止于额度耗尽，零更新，版本库不变 | `runs/t14-resampling-budget-{red,green}-20261001/` |
| 用户停止后两次显式接续 | 第一次接续使用剩余额度；第二次已耗尽，不创建新租约，旧原件不变 | `runs/t14-resampling-stop-resume-20261001/` |
| 修改已归档失败的协议原件 | 先复现未拒绝，补齐原件绑定后拒绝且父状态不变 | `runs/t14-resampling-history-{red,green}-20261001/` |
| 子任务留下部分候选目录 | 保留部分文件，只获取一次，不重做训练 | `runs/t14-resampling-partial-20261001/` |
| 子资源释放不明 | 释放故障保持可见，不获取第二个租约 | `runs/t14-resampling-unreleased-20261001/` |
| 没有合格经验 | 两次尝试均保留 `no_eligible_experience`，同一额度耗尽后停止，零更新 | `runs/t14-resampling-unreviewed-20261001/` |
