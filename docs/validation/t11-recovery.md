# T11：恢复监督的合成回放

2026-09-30。实现范围为 [恢复监督回放](../guides/runtime/recovery.md)，跟踪 [Issue #12](https://github.com/supermassiveasshole/horizon5-autonomous-driving/issues/12)。**开发中，Issue 保持开放；FH5 与 Steam 未启动，没有新实机证据。**

## 已验证的软件行为

入口 `run_experiment(RecoveryReplay(...))`，CLI 为 `fh5 recovery-replay`。使用明确标记 synthetic 的任务/UI 信号，输出冻结配置、完整输入、哈希、操作意图、新片段及失败记录。没有 Windows 适配器或控制器操作。菜单确认与历史重建确认由合成环境提供，不证明识别器、实际释放或模型状态重建正确。

42 项专项测试覆盖释放先于倒带、请求与 generation 匹配、UI 时效、恢复后正向中性样本、逆时间隔离、每阶段超时、停滞与断流区分、总耗时和次数限制、停止/故障/记录不完整、配置及信号校验，以及 CLI 从冻结副本精确复算。

最终全量 **469 项 pytest 通过（40.00 秒）**；mypy 检查 37 个源文件通过，Ruff 检查和 121 个文件的格式检查通过。初次全量为 465 项，审查修复增加四项回归后重跑最终全量。

## 可回放场景

示例：`runs/t11-recovery-20260930/example/`。独立场景与冻结副本复算：`runs/t11-recovery-20260930/audit-reviewed/`；完整列表与结果为该目录的 `results.json`。原先九场景记录保留在 `audit/`，不覆盖。

| 场景 | 最终原因 |
| --- | --- |
| 一次恢复后收到到达信号 | `finish_observed`，原尝试仍失败 |
| 模式不支持倒带 | `rewind_unavailable`，无倒带意图 |
| 缺少解除输入确认 | `phase_timeout` |
| 旧请求号或旧历史 generation | `invalid_acknowledgement` |
| 连续新鲜静止观测，恢复也无确认 | 先保留 `stalled` 失败，再 `phase_timeout` |
| 观测中断 | `observation_timeout`，不追加驾驶失败 |
| 未解释的逆时间样本 | `invalid_forward_sample` |
| 中途记录结束 | `trace_ended` |
| 恢复核验期间再次确认严重偏航 | `failure_during_recovery`，保留第二次失败，不许可驾驶 |

以上共 10 场景全部符合独立预期，从保存的输入/配置副本复算结果完全一致。示例恢复墙钟为 0.6 秒，来自合成时钟；不能作为真实倒带延迟或成功率。10 份 HTML 的静态解析内容与 JSON 一致；未做浏览器视觉验收，不声称页面交互验收。

## Spec

初审发现一项 P2：恢复核验阶段忽略新的确认失败，可能继续许可驾驶。先在释放等待、倒带等待、返回等待及历史预热四阶段建立失败回归，再修复为保留失败、关闭恢复并停止。审查者重放原反例，确认在 0.65 秒停止，无新片段和 `allow_driving`，恢复成功数为零。复审无剩余问题。

最终两轴剩余发现：Standards 0、Spec 0。已披露的实机验收缺口仍存在，不属于软件回放通过即可关闭的项目。
