# T09 / #10：自动局部起跑的独立证据

2026-10-01。本切片为冻结评估增加显式自动起跑任务：把菜单准备、完整驾驶包流和实际数值执行绑定到同一槽位，离线重新核对原始画面与遥测。未启动 FH5/Steam、原生采集、游戏 UDP/XInput 或虚拟手柄。#10 保持开放，软件证据不替代实机验收。

## 行为与边界

任务 v2 冻结赛事配置、菜单模板、条件依据及交接期限，采用局部规则 v3；原人工置位任务和结果不改写。每次开始/重开拥有独立准备记录，后续审核可从原始像素重建菜单状态，从包流核对停车与首个驾驶状态，从成功命令日志核对交接时间。通过只能消除起跑这一项缺口。

其他合法性覆盖仍由独立证据提供。无法打开策略接收器的已开始槽位保留接口异常；重开准备尚未确认的后续槽位明确未开始。错误起跑不能靠删掉尝试获得好成绩。`unattended`、全程有效性、真实驾驶能力和自动晋升均不放行。配置与回放操作见[评估说明](../evaluation.md)。

## 保留原型

`runs/t09-automatic-start-20261001/` 保存一次实际 CPU BC 训练、冻结权重、三种批次、原始菜单画面/遥测/命令及 `summary.json`。响应动作的合成环境采用“有油门则前进、到 3 m 终点停止”的简化规则，不能用于推断车辆动力学或驾驶上限。

- 正常批次两轮各运行 2 秒，实际策略共发出 78 条非零命令，两次起跑均核验。补充独立合成合法性依据后，两次成为局部 `valid_complete`；正式全程和自动晋升仍为 false。
- 第二轮无法识别重开画面时保留第一轮，第二轮未开始；第一轮的准备仍能独立复核。
- 交接期限耗尽时保留已请求启动的一次尝试，后续未开始；非零命令为零，已核验起跑为零。
- 原训练权重字节保持不变。所有原型和依据均标明 synthetic，不冒充人工或实机证据。
