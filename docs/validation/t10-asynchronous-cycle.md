## 可观察结果

通过已确认的 `run_experiment` 入口运行 `SACRealtimeCycle`。
使用实际小型 CPU BC/SAC；外部适配器提供响应命令的合成图像、遥测、输入发送和独立任务依据。
该适配器不模拟 FH5 车辆物理，也不证明实际驾驶收益。

- 连续两次异步运行分别使用冻结策略。每次先解除输入、关闭采集/推理/存档，再整理经验和学习。
- 每轮实际完成 2 次更新，累计从父检查点的 3 次增至 5、7 次；第二轮采样身份等于第一轮新候选。
  父权重字节不变，完整重载预测相同，可靠默认版本不变。
- 外部停止保留原始遥测与执行证据，不进入学习或再次采样。
- 发送异常、运行级释放未确认均停止；环境级关闭成功不能覆盖释放失败。
- 动作幅度、参考槽位或动作历史时刻与训练契约不一致时，在取得外部输入前拒绝。
- 没有独立任务核验时保留采样，但合格转移为零，不训练。

## 原生采样与候选交替增量（2026-10-04）

父版本 `f8887d9`，实现 `7442f00`，审查修复 `1e4f680`。本片接通 #11 的原生采样适配器，
不开放 #15 上层调度的原生恢复，也不完成整票实机验收。FH5、Steam、真实 DXGI、手柄和 CUDA 未启动。

`SACRealtimeStart` 将当前冻结候选、摘要、探索种子、执行配置和停止回调交给适配器。
`NativeSACSamplingEnvironment` 在静态条件核对后，先通过既有菜单流程重开并确认停车、释放资源，
再为本轮候选执行只读 shadow；完整资格通过后才获取受保护驾驶入口。
交接期限从菜单确认就绪的原时刻计算，包含 shadow 用时，不刷新已有期限。

两轮测试使用实际 CPU BC→SAC、生产图像处理/线程、回环 UDP 和响应命令的模拟外设。
第一轮封存的新候选成为第二轮的采样模型，种子与 shadow 同步更新；各轮实际更新 2 次，
原模型不改写，重载预测相同，可靠默认版本不变。设备的 native 身份仅用于测试软件接入，
模拟世界不代表 FH5 物理或驾驶资格。

独立审核回调缺失时，保留采样原件，合格经验为零，不学习；重开失败保留前一轮候选，
不取得下一轮驾驶设备。文件停止及外部 F8 信号在 shadow 中到达时，已运行的菜单被释放，
不继续驾驶或学习。条件不符或缺少 live 时，不获取设备。
这里尚未提供能自动识别蹭墙、草地捷径等行为的真实游戏独立观察者，不能把这些检查默认为通过。

异步循环移除配置外的 10 轮、1000 次更新及预测帧总量 512 MiB 门槛。
父结果只保留诊断计数、必要学习进度及 replay 路径/摘要；明细保留于原 replay，
已释放设备不在适配器中随轮数累积。同步路径及其他旧边界未在本片全量清理。

### 失败证据与修复

- 首版新集成用例出现 **3 failed / 3 passed**：同一配置文件被两次独占创建。
  现分别保存 shadow 配置与取得资格后的驾驶配置，不覆盖历史。
- 初次相关回归 **20 passed / 5 failed / 209.00 秒**：新增 `live:false` 改变合成子任务协议，
  旧恢复与重试的严格比对拒绝它。修复保留合成协议原结构，不放宽恢复核对。
  证据为 `runs/native-sac-cycle-regression.xml`。
- 独立审查发现先 shadow 后重开的顺序会卡住已经驶离起点的车辆。
  外部场景明确停车在距起点 3 米处、仅成功菜单启动才复位，修复前无法进入采样。
  同时，父结果重复保存逐条诊断的反例失败。**2 failed / 11.94 秒**，
  `runs/native-sac-cycle-review-red.xml`；随后调整顺序及诊断存储。

最终相关组合 **33 passed / 280.51 秒**，`runs/native-sac-cycle-reviewed.xml`：

这是相关回归，不是最终版本的整仓套件；早先失败记录保留。
