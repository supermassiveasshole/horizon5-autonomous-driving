2026-10-02，基于 `5e90bcd`。FH5、Steam 保持关闭；没有运行原生截图、Windows 桌面、UDP 或手柄。#10 保持开放。

## 实现范围

版本 3 冻结数值输入条件和实际推理设备，复用 #9 的候选/只读时效资格。`evaluation-run` 默认仅检查，显式 `--live` 才走顺序的菜单准备 → 资源释放 → 冻结 BC 驾驶 → 完整记录和独立重放；1–10 次无参考尝试、单次最多 30 秒。版本 1/2 的合成接口保留。

菜单截图适配使用 DXGI 原始数值像素，内存转灰度、缩小、保留源时间；允许暂时没有新帧，但不将重复像素重新标为新鲜。控制与写盘沿用现有运行模块，不新增 JPEG 依赖。菜单释放失败、配置变化和重开不确认会停止批次。

## 验证方式与结果

通过既定 `run_experiment` / CLI 入口使用实际两步 CPU BC fixture。只模拟外部文件、截图、遥测、桌面和控制器；没有替换模型或内部判定。用于打开原生软件分支的条件文件显式带有 `test_fixture: simulated external files; NOT real capture qualification`，不能当作实机来源，也没有修改旧权重来冒充可驾驶候选。

- `t09-native-batch-red/green-20261002`：版本 3 原先被拒绝，接入后冻结条件和 CPU 设备，**1 passed / 3.03 秒**。
- `t09-native-run-red/green-20261002`：实际模型完成两次模拟设备驾驶、中间重开，输入和成功动作历史可独立复现，**1 passed / 17.18 秒**。两次起跑及执行证据绑定，不允许自动晋升。
- `t09-native-cli-red/green-20261002`：原先 CLI 不识别命令；默认检查通过且不打开设备、不创建运行输出，连同前两项 **3 passed / 22.05 秒**。
- `t09-native-guards-20261002`：缺 live、时长超限、旧批次和采集条件变化均在菜单/驾驶设备取得前拒绝；第二次重开失败保留第一次尝试和未启动槽位，**8 passed / 48.39 秒**。
- `t09-native-boundary-20261002`：第一次设备关闭后配置改变，第二次菜单不打开；DXGI 菜单输入的暂时无帧可恢复、窗口边界/重复帧拒绝且解除输入，**4 passed / 13.33 秒**。

上述目录位于本地忽略的 `runs/`。`t09-native-regression-20261002` 覆盖新入口、现有冻结/执行/起跑/回放及数值驾驶 CLI，**96 passed / 258.89 秒**，JUnit 为同名前缀加 `-results.xml`。

另发现候选比较未包含设备条件：`t09-device-comparison-red-20261002` 复现 CPU/CUDA 混用未拒绝；修复后同设备可正常诊断比较、异设备在输出创建前拒绝，**2 passed / 11.21 秒**（`t09-device-comparison-green-20261002`）。这里只声明 CUDA 配置，未打开 CUDA；版本 1/2 条件格式保持不变。Ruff、123 个源文件的 mypy 通过。

候选比较/菜单回归 `t09-selection-event-regression-20261002`：**73 passed / 83.66 秒**。主分支 `5e90bcd` 的全量测试独立运行，不覆盖当前分支。

## 双轴审查与修正

对 `5e90bcd...e7cd102` 的只读审查：Standards 1 项实验入口依赖具体适配器的规范问题；Spec 2 项缺陷（截图关闭未确认仍允许交接、版本 3 的 CUDA 声明可走旧 CPU 合成路径）。`t09-review-red-20261002` 的 5 个公开入口反例全部失败后修正：核心使用资格协议、原生截图释放必须确认、新版本拒绝旧合成执行且独立回放也检查来源/设备。`t09-review-green-20261002`：**5 passed / 33.66 秒**。

进一步复现菜单取得失败却误报资源全部释放：`t09-menu-acquisition-red-20261002`。未知的取得/清理结果保留为未确认，不继续打开驾驶设备。审查后组合回归和最终复审结果随后记录。
