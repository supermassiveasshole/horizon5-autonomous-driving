2026-09-30。实现 `72bb881`，来源资格修复 `0b5156c`。本切片接通固定选择 → 数值 BC 输入 → 现有 Δt BC 训练/加载/回放，不表示 #38 或实机驾驶验收完成。

## 已实现的软件行为

- `collection-bc-prepare` 复核固定来源后，逐字节复制 RGB 数值数据。尺寸、实际帧时间、预处理与来源布局保留；不经 JPEG 或再次缩放。
- actor 只接收本车局部状态、可用图像、严格截止之前已知的动作历史及可选局部参考。监督标签、世界坐标、来源/尝试身份留在 actor 外。
- 可选独立路线按哈希复制再加载，仅改变配对参考分支。没有参考时明确为空 mask，不声称已经验证有参考驾驶。
- `dataset.json` 只含 train/development；`evaluation.json` 独立封存。正常训练报告与回放不产生最终留出预测，最终评估入口仍待实现。
- 模型保留来源的 `diagnostic_only` 限制，资格未知时也保持诊断状态。审查发现的顶层 false / 来源 true 矛盾已用入口回归修复。

## 480×270 并发原型

本地证据：`runs/t38-numeric-480-reviewed-20260930/prototype.json`、`numeric/report.html`、`model/report.html`、`replay.html`。输入是合成常色 RGB、合成遥测和实体输入格式；使用真实封存/导出/训练代码，没有游戏、截图、UDP、XInput 或虚拟手柄。

1. 后台采集线程封存第一块后冻结数据选择；后续块继续生成。
2. 从固定选择导出数值训练文件，并单独保存最终留出。
3. CPU 执行 8 次训练更新，再从磁盘加载模型回放。模型输入为 480×270，61 个独立帧身份对应解码预算 23,716,800 字节。
4. 训练和回放共约 14.53 秒；此时采集从 1 块增长至 37 块，旧选择与训练文件字节不变。
5. 70 条配对视图预测重载最大误差 **0**，容差 `1e-6`。报告仅包含 train/development，模型顶层及 provenance 均为诊断用途。预览资产引用无缺失。
6. 随后正常停止采集：762 行全部写入，39 块（末块为结束时封存），零丢弃、零未封存行，归档及来源资源正常释放。

训练数据 SHA-256：`2a5db8da7432422e19992c72cef30d55cb211f719c8a9108b8aebbc0efc3dae4`。该原型验证并发与快照隔离，常色图会降低实际存储负担；不得外推为真实多圈磁盘压力或 4K 游戏/GPU 性能。

较早的 `runs/t38-numeric-software-20260930/` 使用 64×36、64 次 CPU 更新，70 条预测重载误差同为 0；它保留修复前的来源标记错误，仅作为历史诊断记录，不替代上述最终原型。
