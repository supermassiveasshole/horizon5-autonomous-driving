# T14：异步采样接入连续学习循环

日期：2026-10-02。GitHub #15 的软件增量，基于 `62f8c1b`。
FH5、Steam、原生截图、游戏 UDP、手柄和 CUDA 均未启动；整票保持开放。

## 实现与可观察行为

`LearningLoop` 配置版本 3 使用既有异步数值运行器采样，再依次进行经验准备、实际 SAC 更新、
冻结评估和候选保存。每次采样释放后才进入学习；下一轮使用新探索版，未通过独立资格的候选不会
替换可靠默认。版本 1/2 的同步输入和更新规则保留。

每轮更新额度为合格新转移数与 `max_updates` 的较小值，分别报告经验数与更新预算。
停止后显式接续只补原预算内的剩余更新，不因存在更多经验就自动追加训练。

子任务已封存、父状态尚未登记时，恢复核验原始执行清单、命令/遥测账本、数值图像、独立依据、
冻结配置及完整 learner。已封存零更新发送失败可按配置有限重试，保留原失败和新尝试的独立目录。

未替换策略、学习器、奖励与恢复校验。合成外部响应不模拟 FH5 的真实车辆动力学。

- 两轮循环：配置版本 3 尚不支持时先复现失败；实现后实际完成四次更新、两轮冻结评估与保存，
  下一轮使用上一轮模型，可靠默认保持原样。单项 **1 passed / 188.34 秒**。

## 双轴审查与修复

初审固定 `62f8c1b...6610f2f`。Standards 没有规范违反，提出一项预算计算重复的可行动建议；
`1664725` 将执行、计数、封存恢复和续训统一到同一预算规则，测试保留独立预期次数。

Spec 指出一项 P2：异步子摘要包含逐帧诊断，允许时长内的记录可能超过父登记/恢复的旧 4 MiB 上限。
通过扩展外部帧标识构造短回合，复现 **1 failed / 87.29 秒**。最外层错误是父摘要超过读取上限；
后续核对发现内部也触发了日志单行上限，实际更新数为零。此前“模型完成更新”的描述不准确，现予更正。
没有替换模型、学习器或故障处理。

`1664725` 曾将摘要阈值提高到 256 MiB。用户明确要求从结构上处理数据增长，因此撤回此问题已经修复的结论。
该版本回归实际为 **14 passed / 2 failed / 403.64 秒**；两个较大记录用例仍被日志单行大小限制拦截。
结果为 `runs/t14-async-reviewed-20261002-results.xml`。

当前改为原件磁盘索引、流式哈希和紧凑摘要；日志按行读取，不以总大小、单行大小或事件总数拒绝记录。
原始执行报告仍保存完整诊断，新的子摘要只引用它。旧索引格式继续兼容，原件完整性要求保留。
结构验收经 `run_experiment` 先失败 **1 failed / 8.04 秒**，再通过 **1 passed / 5.65 秒**，
实际完成两次 CPU SAC 更新。随后异步模块复测 **14 passed / 3 failed / 301.46 秒**：
新增索引文件被旧目录枚举误计为采样尝试；两项较大记录则继续暴露输入元数据的 1 MiB 拒绝阈值。
修正目录枚举及输入读取后，7 项连续学习测试通过，**7 passed / 385.63 秒**，包括两项较大记录的完整训练与接续。

## 2026-10-04：原生适配器的连续调度

版本 4 将已有原生采样、SAC 更新、确定性重复评估和开发候选库接到同一 `LearningLoop`。
每轮使用最新完整探索模型；采样与评估分别取得当前模型及探索模式的只读检查依据，顺序释放
菜单、采集和控制资源。父循环汇总实际发送与释放结果，旧合成版本的来源及存档格式不变。
显式原生启动和接续才接受 `live=True`；来源不符在设备获取前拒绝。

恢复核验父配置确定的来源、模型、部署/采集配置、菜单、数值输入、独立证据和已封存结果。
子采样或评估完成后、父状态记账前退出，可以接纳原结果，不重复采样或更新。
没有独立审阅器时保留录制、零新增合格经验、零更新；没有默认认定合法驾驶的替代逻辑。

首次原生循环软件测试 **5 passed / 190.67 秒**（`runs/native-loop-green5.xml`），包括两轮实际
CPU SAC 更新、更新模型的探索/确定性检查、缺失审阅和两个真实子进程退出恢复边界。
相关合成循环、原生采样与重复评估 **21 passed / 337.64 秒**（`runs/native-loop-related.xml`）。
外部相机、菜单和响应命令的世界均为模拟设备，`native` 是边界身份测试，不能冒充 FH5 证据。

测试还暴露决策启动前未处理过期动作租约：新推理绑定了旧上下文，随后被拒收。
`8c99793` 在绑定上下文前先执行既有监督规则，并刷新实际时钟；期限和解除输入逻辑未放宽。
公开入口先复现失败，再通过相关实时模块 **38 项 / 4.38 秒**。

较早兼容回归因 C 盘实际写满而出现 2 项错误，不能计为通过。只清理已结束测试的已核对
临时目录，保留 JUnit 与诊断结论；随后上述 21 项包含原失败的大记录用例并通过。
模型训练没有被替换，未增加文件大小门槛。原生测试沿用显式最小 Windows 计时周期及
单 CPU 线程条件，结束时恢复计时设置；这不证明默认系统调度或跨线程精确回放问题已解决。
