# 连续学习循环（T14 / #15）

`LearningLoop` 将 SAC 采样与续训、冻结评估、候选保存串成按配置轮数执行的运行。外部环境响应模型实际命令，Torch 实际更新网络；常规轮次不需要新增示范、人工重开或逐轮批准。版本 1–3 使用合成环境；版本 4 接入原生短段适配器，启动和接续均须显式 `live=True`。软件运行通过不代表 FH5 驾驶能力改善；#15 保持开放，实机验收另行记录。

## 启动

输入已有[候选版本库](candidate-store.md)，其中默认版具备独立合成评估依据，探索版含完整续训状态。配置路径相对配置文件解析：

```json
{
  "version": 1,
  "store": {"directory": "../runs/versions", "revision": "<当前版本摘要>"},
  "registry": "../runs/evidence-usage.sqlite",
  "recording": "policy-record.json",
  "task": "local-task.json",
  "reward": "local-reward.json",
  "rounds": 2,
  "steps_per_attempt": 16,
  "evaluation_seconds": 15,
  "seed": 191
}
```

```python
from pathlib import Path
from fh5.experiment import run_experiment
from fh5.learning_loop import LearningLoop

result = run_experiment(
    LearningLoop(Path("configs/learning.json"), Path("runs/learning-001")),
    learning_environment=environment,
)
```

输出目录必须全新且在版本库之外。轮数由调用方给定正整数预算，不再额外限制为 10；每个新接纳转移至多获得一次更新。旧同步采样器仍有单次 1–1000 个动作的实现限制，当前重复评估器仍限每批 1–10 次，尚未在本切片清理。评估沿用默认版的冻结条件、门槛、任务、原始起跑模板和无参考输入协议，关闭探索。配置和原始依赖必须保留，不支持悄悄换奖励、路线或像素契约后继续原会话。

## 一个外部环境，顺序交接

### 阶段历史与恢复状态

阶段明细按调用写入 `diagnostics/stages-<唯一标识>.jsonl`，不再整段嵌入父状态，也不因达到
1,000 个阶段而停止。`state.json` 的 `stages` 使用 `learning-stages-v1`：累计事件数、最近
两个阶段和当前日志描述。最近阶段仍用于采样结果恢复；已封存的续训进度直接由 checkpoint
确定，不依赖阶段日志。配置、模型、原件与子资源释放的核验继续执行。

每段首行保存前段描述及 `base_events`，后续逐行记录阶段；描述中的记录数包含首行，SHA-256
绑定该记录数对应的原始字节前缀。接续会新建段，旧段不追加、不覆盖；进程意外退出后未被父状态
确认的尾部保留，但不算入已确认历史。离线审阅可沿首行的前段描述逐段读取并校验前缀，无需一次
加载全部历史。旧数组首次接续时逐行迁移；旧父状态不再受 4 MiB 文件门槛限制，但旧 JSON 首次
解析仍需与其大小相应的内存。

日志是可选诊断，创建、写入、刷新或关闭时的资源故障明确记录为不可用；累计数与最近阶段仍
写入父状态。历史文件缺失不会阻断已封存 learner 的恢复，也不会被宣称为完整审计记录。
轮次、恢复事件和报告发布的其他增长结构及旧上限仍在清理，见[审计记录](validation/resource-limit-audit.md)。

### 版本 3：异步数值采样

版本 3 保留同一学习入口、评估、版本保存及停止/接续机制，将同步的 `steps_per_attempt`
替换为 `sampling`：

```python
from dataclasses import asdict
from fh5.realtime import RealtimeConfig

# config 是上述既有配置；像素及槽位取自要加载的模型。
runtime = RealtimeConfig(pixels=trained_pixels, reference_count=trained_reference_count)
config["version"] = 3
config.pop("steps_per_attempt", None)
config["sampling"] = {
    "runtime": {**asdict(runtime), "pixels": runtime.pixels.metadata()},
    "seconds": 10,
    "max_updates": 8,
}
```

`runtime` 是包含 `pixels` 和 `action_offsets_ms` 等运行参数的对象。
加载时补齐并冻结运行器默认值，保存到会话配置；后续接续不得悄悄改变它们。
采样时长须为正有限值，并满足所用执行器的运行条件；`max_updates` 是调用方给定的正整数预算，不再额外限制为 1000。每轮实际更新预算取新合格转移数与 `max_updates` 的较小值。
合格经验数量与更新预算分别记录，完成低更新比训练后不会自动补到全部经验数量。

版本 3 的 `LearningEnvironment.sampling(identity)` 返回 `SACRealtimeEnvironment`，其
`start(SACRealtimeStart)` 接收当前候选、摘要、探索种子和协议，返回一次异步 `RealtimeEnvironment`。图像、遥测、推理与动作监督使用
现有数值运行器；`finish(recording_dir)` 仍提供独立任务依据。只有运行器与采样租约都确认释放，
才进入经验准备和学习；冻结评估继续使用 `evaluation(identity)`，两类资源不同时持有。

版本 3 仍限合成外部 I/O、实际 CPU 模型；原生适配使用下述版本 4，不会悄悄改变旧配置的执行来源。
版本 1/2 继续使用同步适配器，不能把旧记录改标签后当作异步记录。
版本 3 可选 `storage` 和 `storage_monitor`（后者要求前者），支持既有有限获取重试和采样重试设置。

恢复时核验异步执行清单、命令/遥测账本、归档的数值输入与 RGB、独立任务证据和完整 learner。
异步运行配置、采样模型及探索种子须匹配父协议。子任务已封存而父状态尚未登记的情况，可接纳已有结果；
停止训练后只补该轮预算内尚未执行的更新，不重采样、不重复计经验。失败重试仍须确认释放且没有模型输出。

异步子摘要保存计数和原始执行位置，不重复嵌入逐帧诊断；原件目录保存为独立 SQLite 索引，
摘要绑定索引的路径与哈希。登记、接续和失败重试逐项读取索引、流式计算原件哈希，继续检查必要原件
是否完整。旧的内嵌原件目录仍可读取。这部分不再使用 4 MiB 或 256 MiB 的文件拒绝阈值。
其他历史记录仍有待清理的固定限制，见[资源限制审计](validation/resource-limit-audit.md)；
本文其他章节记录的旧上限是当前实现限制，不能作为其合理性依据。

SQLite 原件索引先分块复制到私有临时快照，校验该快照后以不可变只读模式查询；不读取未绑定的旁路日志。
带摘要的 JSON 对同一份解析字节校验，不使用“校验旧文件后重新打开新文件”的读取方式。

学习器先封存完整模型和必要训练状态，随后流式生成 HTML。HTML 写入或内存分配失败只在返回结果的
`presentation` 中记录，`report_path` 返回已存在的 JSON 结果。SAC 采样循环和父循环的展示采用相同规则。
重载诊断的 JSON 副本也按需发布，失败记为 `diagnostic_export`；即使展示文件均不可写，也保留数值检查结果，
返回已有模型清单的位置并继续登记已封存候选。必要模型、训练状态与经验文件不属于这种可忽略的展示副本。
冻结重载的数值检查仍必须成功，不能把计算或原件错误当作页面故障忽略。`sac-policy-replay` 可在新的报告路径
重建冻结推理诊断，不能因此获得新的训练或评估资格。必要模型/经验文件自身写入失败仍是资源故障；
这次修改不宣称所有采集、BC 或评估页面均已隔离。

实际软件验证及限制见[异步连续学习记录](validation/t14-asynchronous-learning.md)。

### 版本 4：原生短段循环

版本 4 沿用版本 3 的配置字段，但要求 `native_development_only` 候选版本库，以及
`NativeLearningEnvironment`。合成版本库不能改标签后复用。调用示例：

```python
from fh5.learning_native import NativeLearningEnvironment
from fh5.learning_loop import LearningLoop, LearningContinue

environment = NativeLearningEnvironment(
    Path("configs/numeric-drive.json"),
    Path("configs/event.json"),
    shadow_seconds=shadow_budget_s,
    handoff_timeout_s=task_handoff_s,
    review=independent_review,
)
result = run_experiment(
    LearningLoop(Path("configs/native-learning.json"), Path("runs/learning-native"), live=True),
    learning_environment=environment,
)
```

采样使用最新完整探索版：完整重开 → 当前模型与探索种子的只读检查 → 有界驾驶 →
释放输入 → 独立结算 → SAC 更新。随后对新候选另做关闭探索的只读检查，再按冻结批次
重复评估并保留版本；失败或未胜出不丢弃学习进度。菜单、采集与手柄沿用既有原生适配器。
本入口仍受既有低速短段控制条件约束，未扩展为全程驾驶或自主倒带。

`review` 必须返回独立观察证据。省略它时保留原始采样，但不产生合格经验、不更新模型；
软件没有自动识别 FH5 蹭墙、捷径等全部违规的能力。测试外设提供的独立世界状态不能当作游戏识别结果。

接续使用新的同配置环境和 `LearningContinue(run_dir, live=True)`；`expected_state_sha256` 仍为可选精确断言。
父状态绑定部署配置、采集配置、路线、菜单原件及检查预算；评估还绑定新模型的确定性
资格原件。恢复重新核对这些绑定、实际执行与完整 learner；已封存子任务可以接纳，不重复采样。
实际发送命令与资源释放据实汇总，正式驾驶能力和驾驶改善标志继续保持未验证。

### 同步适配器与公共评估接口

`LearningEnvironment` 提供 `source_kind="synthetic"`，以及：

- `sampling(identity)`：返回一个 `SACEnvironment` 租约，负责合成重置和响应实际策略动作。
- `evaluation(identity)`：返回一个 `EvaluationEnvironment` 租约，使用原始菜单画面、遥测与动作执行完整重开，再运行冻结模型。首个评估槽位也从驾驶场景重开，不假设调用方已放回赛前页。
- `review(recording_dir)`：返回独立观察者的证据文件，或 `None`。循环不会把执行完成、模型预测或训练奖励翻译成合法驾驶证明。
- `close()`：释放该后端拥有的资源并报告结果。

后端必须独占同一实例的采样/评估资源；每个子租约关闭后才能创建下一个。采样租约在更新之前释放，更新期间不持有驾驶输入。版本库另有 OS 锁，防止两个调度者同时推进同一会话；过期版本不能覆盖已提交选择。底层同步合成调用仍须有界，此入口不提供原生硬实时保障。

## 探索进度与默认版分开

每轮执行采样 → 独立结算 → 更新并重载完整模型 → 冻结评估 → 保存选择。新采样绑定确切模型摘要，工厂打开期间换成另一份合法模型也不能接管此次采样。

候选证据不足或没有胜出时保留默认版，但下一轮使用刚完成更新的探索版。`latest_learner` 是最近封存的训练状态；`explorer` 是最近完成评估和版本保存的探索状态。两者可在评估故障时暂时不同，不能把旧的已评估版本当成最新学习成果。

`state.json` 保存阶段时刻、完整轮次、有效转移、更新数、模型身份和故障，作为结果与接续的同一份依据；`report.html` 仅用于展示，不可写时返回已保存的 `state.json`。根目录不再生成重复的 `summary.json`；旧文件保留但不读取或刷新，读取循环结果的脚本应改用 `state.json`。每轮子采样目录的 `summary.json` 仍是必要原件，保持不变。每轮另保存完整 learner、冻结批次、全部评估尝试及比较依据。未开始槽位仍列出；正式驾驶能力与提升标志始终为 false。

## 获取环境时的有限重试

版本 1、2 的配置均可增加可选项；省略时不自动重试：

```json
"acquisition_retry": {"max_retries": 2, "delay_seconds": 0.2}
```

`max_retries` 为调用方给定的非负整数，表示首次请求之外的重试次数；`delay_seconds` 为非负有限等待。两者不再额外套用 3 次和 5 秒上限。预算分别作用于每一轮的采样、评估获取过程。等待期间持有零个驾驶租约，检查用户停止；每次重试前重新核对冻结输入、版本库与容量。失败记录保存在 `acquisition_failures`，含阶段、轮次、次数、原因、资源释放状态及接续序号。

只有 `LearningEnvironment.sampling()` / `.evaluation()` 明确抛出 `fh5.learning_io.LearningUnavailable(reason, resources_released=True)` 才自动重试。适配器须先释放失败获取中已分配的资源，再作该报告；普通异常和释放不确定的错误直接停止。后端整体关闭成功不能覆盖子资源的释放失败。该机制限制次数和等待，不会抢占一个不返回的外部获取调用；适配器自身仍须遵守响应期限。

预算耗尽返回 `acquisition_retries_exhausted`，保留已有 learner、失败历史及版本库。显式调用 `LearningContinue` 开启新一轮获取预算，并以新的接续序号追加历史；循环不会自行不断重新调用接续入口。已有驾驶尝试不参与这类重试，不覆盖已有采样/评估目录，也不重新训练已经完成的候选。

如果停止请求在获取连接期间到达，连接返回后直接关闭，不开始菜单操作、驾驶或创建空子任务。关闭失败按释放故障停止，不能把它重新分类为获取失败并再开一个连接。

上一轮子资源未确认释放时，显式接续也会在获取新连接前拒绝，并保留原会话文件。重试核对涵盖当前完整 learner，以及已准备评估的配置和全部冻结批次原件；不能先获取第二个连接，再由子任务发现候选输入已经变化。

## 已封存采样失败的有限重采样

各版本可额外配置 `"sampling_retry": {"max_retries": 1}`。非负整数预算表示每轮首次采样之外允许的新尝试次数，不再额外限制为 3；省略或 0 保持原行为。额度覆盖该轮的全部显式接续，不因进程重启或调用 `LearningContinue` 而重置。它与尚未打开环境时的 `acquisition_retry` 分别计量。

仅在子任务已经返回并封存失败摘要、明确释放全部资源、没有任何 learner 更新或候选输出时重采样。适用失败为 `sampling_fault` 和 `no_eligible_experience`；用户/资源停止先结束本次运行，解除条件并显式接续后才可消耗同一额度再尝试。存在部分候选目录、存档损坏或释放不明时仍拒绝自动重采样，不能把已发生但尚未确认的训练丢弃后重做。

原 `learning/` 目录保持不变，后续尝试使用 `learning-001/` 等新目录、独立接口身份和确定的新种子。`sampling_history` 保留旧摘要绑定；同级 `learning-originals.json` 保存 `sampling-source-index-v1` 描述符，绑定 `learning-sources.sqlite3` 的位置和摘要。逐文件路径与哈希留在磁盘索引中，不再因清单超过 64 MiB 拒绝恢复，也不一次构造完整路径字典。

接续从校验过的私有副本逐项核对全部原件，包括新增、改动或缺失文件。旧路径→哈希 JSON 清单逐项导入临时 SQLite，保留原字节、摘要和重复键的最后值语义。索引或描述符发布后进程退出，重入先核对已发布内容，再完成缺失发布，不覆盖原档案或重置已用重试额度。实际磁盘或读取故障明确停止，原件保持不变。当前 `learning` 绑定最近一次结果；外部独立审阅附件仍纳入接续核验和容量计量。父状态的其他增长结构不属于这项迁移。

父目录或当前采样子目录的 `stop.request` 都会结束本次运行；不能把子任务的 `stop_requested` 当作普通失败自动重试。之后显式接续使用新目录，旧子目录中的停止标记作为历史原件保留。

失败尝试不产生训练更新额度；只有后来真正接纳的数据才能获得更新。每次重试重新验证冻结输入、当前完整 learner、版本库和容量。次数耗尽保存 `sampling_retries_exhausted`，保留所有尝试、模型和失败原因；`recoveries` 记录尝试编号、原目录及重采样原因。该机制不覆盖强杀后的未封存目录，也不启用评估失败重跑。

## 停止与接续

已停止写入的会话可先运行[学习记录容量清单](learning-storage.md)，计量原始依赖及保留版本；它不替代下述接续核验。版本 2 配置额外要求 `storage`，在初始化复制、采样、评估和版本归档前检查容量，不足时以 `storage_budget_exhausted` 停止。容量恢复后可按当前状态摘要接续。版本 1 不启用这项检查；声明的阶段/停止余量不是文件系统硬配额。

在输出目录写入 `stop.request`。采样在响应边界停止，训练在完整优化器更新边界封存；评估的菜单输入、状态读取、停止监视和下发前均检查停止，解除命令仍允许执行。子租约解除失败不能被后端的成功关闭掩盖。

解除停止条件后，通过 `LearningContinue(run_dir)` 和同一实验入口接续。程序取得版本库的独占锁后，自动绑定当前 `state.json` 的原始字节摘要，并核对实际解析的内容，调用者不再需要手工计算摘要。需要限定某次已查看状态时，仍可传入 `expected_state_sha256`；不匹配则拒绝且不改写原会话，不自动改用最新状态。

接续会核验配置、完整 learner、已保存采样及评估绑定。采样结束后单独绑定原始动作轨迹、遥测、数值图像和独立审阅附件（包括环境返回的外部路径），不能只凭派生 replay 或结果摘要验证原件。缺少原件绑定的旧会话拒绝自动接续；独立完整 learner 的恢复规则不变。

目前支持已封存阶段的接续：训练完成但评估接口尚未打开时直接评估该模型；评估中停止且已封存的失败记录继续保留，不能用重跑替换。历史故障保存在 `interruptions`。不重复采样或给相同经验重复计算更新额度。

### 更新未用完时的显式接续

采样已经接纳经验、训练收到停止并封存了完整 learner 时，`LearningContinue` 先恢复已封存进度，再补齐原轮次的剩余更新，之后才进入评估。剩余额度等于原轮次更新预算减去已封存的更新数；不重新采样，不把接续本身计为新经验。再次停止时保留仍未消耗的额度，当前调用结束。

每段接续写入该轮的 `updates-000/`、`updates-001/` 等独立目录，保留原采样和旧 learner。模型权重、完整训练状态及必要训练依据先保存，`policy.json` 最后发布。接续按目录序号逐段加载完整 checkpoint，核验原始经验、剩余额度、父模型摘要、优化器累计步数、训练配置和未变的 replay。父状态已登记的模型摘要必须出现在这条链中，且该点更新数与父状态相符；其后合法的完整结果也会接纳，不能退回更旧模型重做训练。零更新的停止段仍占用独立目录，不以累计步数猜测下一个目录。接续次数不设 10 段门槛，也不重新授予额度。

父状态只保存当前模型与计数摘要，不再另写或读取 `update-history/` 确认链。接续旧会话时移除
`update_segments` 的旧数组或索引指针，原索引文件和已封存 learner 保持不变；恢复依据是上述
checkpoint 链及父状态已登记的模型绑定。原始经验和每段 learner 仍按需遍历核验，不保证长历史
的恢复耗时恒定。

旧停止记录尚未保存原采样父模型时，先核对当时的探索模型与采样摘要，再持久保存该绑定，即使剩余更新已完成，也避免以后探索模型晋升后失去祖先身份。若更新未完成的旧轮次已经准备或冻结了评估，则在改变父状态、训练或获取环境前拒绝自动接续，保留旧评估及 learner；这类旧记录的自动迁移尚未实现，不能先更新模型再套用旧评估。

本机制处理完整更新边界上的主动停止。完整续训子结果已封存、父循环未登记便退出时，也可按下述规则接纳；未封存的部分文件仍拒绝覆盖或推断成功。基础验证进度见[中断更新记录](validation/t14-update-resume.md)。

### 续训子结果已经封存、父状态尚未登记

`LearningContinue` 从当前轮次的连续 `updates-NNN/` checkpoint 推导实际进度。完整子结果已封存、父状态还未保存时，凭其父模型绑定和训练依据找回进度，不再要求阶段历史先记录进入该段续训。之前轮次完成、子资源释放及原始采样绑定的要求仍保留。

核验通过后补记 `sealed_updates`，仅增加父状态尚未登记的实际更新数；若当前仍有停止请求，则登记后停止。再次接续不重复登记或重复授予额度。剩余更新继续使用新的目录，已耗尽额度则进入该模型的冻结评估。

顺序目录已经存在但未封存完整 checkpoint、模型损坏、祖先或额度不符时，在改写父状态和获取环境前拒绝，保留全部文件，不覆盖目录或退回旧模型继续。这是封存结果的核验与登记，不恢复尚未写完的优化器步骤。验证进度见[续训父状态恢复](validation/t14-pending-updates.md)。

采样子任务已经封存完整 learner、父循环还停在 `updating` 时退出，也可接续：核对该轮配置、种子、原始记录、派生经验和完整 learner 的父模型及更新额度，再补记 `sealed_sampling` 恢复事件。更新已完成时直接进入评估；若子任务因停止封存且仍有剩余额度，则先登记实际进度，停止请求仍在时结束当前调用，解除停止后从该模型补齐原额度。两种情况都不重新采样，重复接续不重复接纳经验。

这一恢复不依赖是否启用 `sampling_retry`。已声明完整模型的停止结果先按 learner 与经验契约核验，不作为零更新失败重新采样。缺少完成摘要、资源未释放、模型损坏、原件变化或计数不一致时，在改写父状态和获取环境前拒绝接纳，保留原会话。它仍不恢复尚未封存的优化器步骤。验证范围见[采样停止父状态恢复](validation/t14-stopped-sampling.md)。

若子任务已经封存零更新的失败，但父循环尚未登记结果便退出，启用了 `sampling_retry` 的会话也可显式接续。先核对协议、模型、种子、释放结果与必要原件绑定，补记 `sealed_failed_sampling`；接下来沿用该轮剩余重采样额度。额度已经耗尽时只登记原失败并停止，不获得新的尝试。失败记录必须绑定采样诊断、遥测与报告；有输入包或动作轨迹时还须绑定轨迹及其引用的全部数值帧，不能漏掉损坏原件的摘要后绕过核验。未封存摘要、部分候选输出和释放不明仍拒绝接续，拒绝时不改写原父状态。

恢复时核对实际尝试目录与原始采样诊断中的包数，不能靠摘要声称零输入或没有尝试而跳过原件。每次新采样另写 `sampling-sources.json`，明确独立审阅文件的位置与摘要（没有审阅则记为 null），并纳入原件清单；接续展开审阅正文及全部附件引用。尚未被父状态绑定的旧失败若缺少这份声明，拒绝自动接纳。已经被父状态绑定的旧重采样记录仍按原摘要核验；既有成功子任务继续按派生 replay 的严格原件绑定恢复。

未登记失败的恢复只适用于 `updating` 阶段；该阶段在采样收尾并释放资源后发布，因此必须保留恰好一次原始尝试。尝试目录整体丢失时，即使摘要同时声称没有尝试也拒绝接纳；父状态已绑定的旧零尝试停止不受此限制影响。

评估子任务已完成并释放资源、父循环尚未发布评估结果时，也可核验后接续。评估在全部工作及自身审阅返回后发布 `completion.json`；接续核对冻结模型、原定条件与时长、菜单配置、已开始/未开始槽位及原始执行，并独立重放数值推理和起跑证据。通过后补记 `sealed_evaluation`，复用原结果，不重新获取环境或重复训练。正常完成的整批评估，以及原件完整但执行中止的计划前缀均可接纳；后者仍保留失败和未开始槽位，完成版本结算后按原中止原因停止，不能变成成功评估。缺少完成标记、原件缺失、审阅被隔离或资源未释放时拒绝自动接纳。

父循环的独立审阅输入先完整保存在 `state.json`，随后原子发布为 `parent-ledger.json`，不修改子评估已经封存的清单。冻结后不再重新请求相同审阅；派生清单尚未落盘时可从绑定状态重建，已存在但不相符的清单拒绝覆盖。外部审阅文件及附件计入容量保留依赖，即使派生清单尚未发布也不能遗漏。

审阅报告已经存在或只写了一部分时，保留旧目录，在 `reviewed-001` 等未占用目录重新核验原始记录。
分配时从 `reviewed` 起检查磁盘上的实际占用，不再维护父状态的目录序号或 `review_publication` 游标。
完整历史留在各自目录，可按需浏览；旧 `review_publication`、`review_directories` 仅保留原值，不参与分配或继续增长。
已有文件、目录或链接均不覆盖；没有发布次数上限，也不因历史游标与目录不一致而拒绝接续。
这些是派生报告重建，不新增驾驶尝试。原始失败、全部槽位、learner 和训练计数保持不变。
旧版本若曾改写已封存子清单而破坏完成摘要，不会在接续时自动重签或修补原件。

父审阅重建保留原评估的用户停止标记。解除停止后接续，会保留中止尝试及未开始槽位、完成该轮结算，再进入剩余轮次；不会因为当前停止文件已移除而丢失原中止原因。

版本提交前退出时，已准备的比较和保存请求必须与本轮状态完全一致，才会继续提交；原文件不会覆盖。版本已提交、会话状态发布前退出时，`saving_versions` 阶段只允许接纳版本库中紧接原版本的一条相符提交。核对本轮请求、冻结评估绑定、完整默认/探索归档和学习状态，再补记已完成轮次；不会重复采样、更新或发布同一候选。其他会话推进、回退及不相符的提交仍拒绝自动接纳。已提交版本的恢复事件另记入 `recoveries`。

接口故障与不能确认重开时受控停止；自动重试限于上述环境获取和已封存零更新采样失败。未封存的采样/评估目录不会自动覆盖或推断成功。强杀后的未封存协调、初次采样中的部分训练结果及评估菜单/驾驶故障的有限重试仍待完善；审阅输入尚未完整冻结前的外部回调可能需要重新读取。已封存完整 learner 可使用既有续训/归档入口恢复。磁盘总预算和长期资源压力由 #16 继续覆盖。
