# 局部路线与进度（T04，开发中）

从已有遥测提取局部参考轨迹，再为它补充独立的可行驶走廊和检查点。当前入口只处理离线数据，不发送游戏输入。路线几何、合法性覆盖与实际驾驶能力分别验收。

## 提取与回放

```powershell
uv run --locked fh5 route runs/manual-001 --output runs/local-route-001 --first-packet 100 --last-packet 900
uv run --locked fh5 replay runs/another-drive --route runs/local-route-001/route.json --report runs/another-drive/route-review.html
```

包编号为录制报告中的 `packet_index`，两端包含；上面的编号仅为示例，应按真实记录选择。输出目录、报告文件必须不存在。路线必须来自同一车型/PI 的一个连续活动片段，不能跨暂停、倒带/重开、断流或坏包；静止记录不能成为路线。游戏计时偶尔重复可以保留，但回退或连续 250 ms 不前进会拒绝。未知边界不会自动生成走廊。

`--spacing` 默认为 2 米，范围 0.25–10 米：沿原始轨迹保留相隔至少此距离的观测点及末点，不生成平滑的虚构位置。三维折线长度和简化误差取决于采样密度；不是官方赛事长度。局部起点、车速和原始包仍可在报告查看。

公开测试边界仍为 `run_experiment`：构造 `BuildRoute(recording_dir, output_dir, first_packet, last_packet, spacing_m=2, annotations_file=None)`，或 `Replay(recording_dir, report_path, route_file=None)`。普通录制与回放不要求路线文件。

## 独立数据与核验依据

路线目录包含：

- `reference.json`：三维观测点、沿线里程、原始包编号、人工/画面核验状态。
- `corridor.json`：单独测得或标注的可行驶区域；空列表表示未知，绝不表示零宽道路。
- `checkpoints.json`：有序检查点门，以及本段检查点是否已全部核对的声明。空列表只有在检查点审查有依据时才表示本段确实没有门。
- `route.json`：格式版本、原始 `packets.jsonl` 和 `session.json` 哈希、选择区间、间距、以上资产和证据的哈希。
- `evidence/`、`report.html`、`report.json`：冻结的标注依据及可独立查看的分析报告。报告自包含，原始记录不改写。

复制 `configs/route-annotations.example.json` 后填写标注，提取时增加 `--annotations <文件>`。所有审查和标注的 `status` 为 `unverified` 或 `verified`；后者必须提供非空 `evidence` 文件列表，路径相对标注文件。程序冻结原文件内容并绑定哈希，回放时检验；哈希发现损坏，不构成防篡改签名，也不自动证明标注正确。

走廊每项格式为：

```json
{
  "id": "survey-cell-01",
  "s_start_m": 0,
  "s_end_m": 4,
  "polygon_xz": [[-1, -1], [5, -1], [5, 1], [-1, 1]],
  "y_min_m": 1,
  "y_max_m": 3,
  "status": "unverified",
  "evidence": []
}
```

这是合成坐标示例，不能用于实机。多边形按边界顺序排列，须严格凸、不自交；弯曲路段拆成多个凸区域。里程范围只声明该区域属于参考线的哪一段，实际覆盖还要检查几何交集及高度。可行驶走廊可以是保守核验区域，不必等于整幅道路边界；区域外不能据此直接判定游戏违规。

检查点每项包含 `id`、`s_m`、`left_xz`、`right_xz`、`y_min_m`、`y_max_m`、`status` 和 `evidence`，按正向里程严格递增。门必须有不同端点。`reference_review`、`checkpoints_review` 分别核对轨迹是否适用及检查点覆盖是否完整，二者也有独立状态和证据。

## 连续定位与已确认进度

定位在三维参考折线上投影；已定位后只搜索上一里程附近的候选。允许变化范围为 `2 m + 1.5 × 相邻样本最大速度 × 有效时间差`，接收/游戏时间差限 0.5 秒，重复游戏时间以接收时间计算并保持 250 ms 停滞限制。多个距离接近但沿线相隔较远的候选保留歧义，不把自交或邻近回程道路当作跳跃进度。

初次观测须在本段起点 1 米里程内、距参考线不超过 2 米；距参考线超过 10 米视为未可靠定位。上述是当前保守匹配参数，随代码版本保存，尚不是闭环性能标定结果。

只有完整观测线段位于已核实走廊、参考轨迹和检查点覆盖均经核验、并按顺序正向穿过检查点门时，才增加 `confirmed_progress_m`。检查的是相邻观测之间的直线近似，不能证明两帧之间没有未观测的小偏离，也不覆盖蹭墙/碰撞等独立有效性规则。

`new_progress_m` 只计算当前连续片段新增的最远进度，往返不会重复领取。出现未覆盖区域、漏门或连续性异常后，本片段锁定确认进度；即使重新贴近参考线也不补算缺失段。新的遥测片段重置起点定位、检查点和最远进度，各段不能相加冒充正式完赛。显示的 `reference_s_m` 只是几何位置，不能替代已确认进度。

检查点门与参考线的实际交点须距离标注里程不超过 0.25 米。斜向门以实际正向穿越为依据，允许相对参考交点提前或延后通过；等待期间不新增确认进度。跨过多个门时按观测线段上的真实交点顺序检查，不能只按标注列表补齐。

报告显示轨迹、走廊、门顺序、当前定位、未知区域和数据质量。`low_speed_ready` 只表示标注审查齐备、参考线全被核实走廊覆盖且门与参考线相交；它不是实机控制授权、正式有效成绩或无人值守验收。真实数据与尚缺准备见 [T04 记录](validation/t04-route.md)。

## 与多模态学习的关系

用户于 2026-09-29 确认直接使用截图、遥测与预录路线做监督初始化，再由 RL 精调；精确分割和米制道路是可选研究。参考轨迹可先用于离线观测/BC，不需要等待走廊、自动重开或传统控制器完成。导航参考应来自独立历史记录并在评估前冻结，不能使用当前待预测回合的未来位置；参考轨迹不等于边界、唯一合法路径或最优赛车线。

实机短段仍须核验有限练习范围、检查点与连续进度，可以只建立小范围保守走廊，不必先测完整路宽或全程两侧。保守区域外是超出已核实范围，不直接等于游戏违规。现有约 801 米轨迹及观察材料保留，真实可信走廊仍未验收；此次调整不改变 `low_speed_ready`、`confirmed_progress_m` 或历史证据。

50 米人工观察不能代表全程路宽，视觉模型也不能自行将估计变为 `verified`。取消分割前置不放宽奖励和正式有效性要求；若以后使用较弱训练进度代理，须另行版本化并验证隔离。完整契约见 [多模态学习规格](multimodal-learning-spec.md)。
