# FH5 模型与自主驾驶策略：推荐方案 v1

2026-09-30。依据用户关于持续 RL、车辆状态与特性学习的要求，以及现有代码、实机记录和一手研究整理。本文给出具体工程推荐；参数是首轮实验起点，不代表已经实现、已验证最优或已经通过实机验收。产品目标仍以 [PRD](PRD.md) 为准，已发布任务不会因本研究自动改变。

## 1. 推荐结论

采用**带时间信息的多模态连续控制策略：少量 BC 初始化 → 双 Q SAC 自主交互改进 → 按证据增加车辆动力学辅助预测**。

真实 RGB 历史负责道路、导航和环境信息；本车遥测与动作历史负责当前车况及响应线索；可选预录航点只提供去向先验。Actor 直接输出转向与有符号纵向动作。Critic 根据实际结果学习价值。后续辅助头学习“这个状态下执行这些动作后，车辆怎样变化”，不把历史赛车线或示范速度固定为驾驶目标。

先完成真实短段闭环。预测头、完整车辆模型、精确分割、GRU、规划器和 QR-SAC 均不新增为首次驾驶前置。当前小 CNN 可继续用于管线诊断；下一版正式表征候选采用预训练 ResNet-18，并以实际驾驶和共享 GPU 延迟决定是否采用。

## 3. 观测：道路信息与车辆特性分别表达

### 图像与时间

- 初始基线使用三帧完整 480×270 RGB，名义间隔 100 ms，覆盖约 200 ms。保留追尾远视角、道路和导航；不套用分类模型默认的中央裁剪。追尾相机会随速度改变距离，不把图像运动全部解释为车辆运动。用户已明确优先 4K 来源，先验证其时效与缩放后的质量，再按需要比较 480×270／640×360 模型输入；1080p 仅作瓶颈诊断或后备，不是首选。来源优先级不代表模型直接输入 4K，见[分辨率与持续采集方案](demonstration-collection-plan.md)。
- 每个槽携带实际源时间差、图像年龄和有效性；历史严格因果且不跨暂停、倒带或重开。按真实时间选帧，不能通过随意修改时间标签制造“时间增强”。
- 模型接收内存中的数值像素。DXGI 采集、预处理、推理与存档独立；不足以组成有效观测时跳过当次决策，旧动作仅在原到期时间内有效。
- 有遥测的状态直接提供给策略，不要求它重新从速度表猜测。视觉仍必须在道路、导航及后续对手交互中发挥作用，分别评估接入、利用和实际收益。

时间特征使用相对秒数并适当缩放，不将绝对时钟大整数转成 float32。HUD 的取舍属于观测版本：可以移除无关显示，但需保留当前选定的导航意图来源；不能在关闭导航线与小地图之后仍声称模型知道陌生路口应往哪里走。

### 数值状态与短期历史

首版沿用已接入的车速、车体速度和角速度，结合已执行命令历史、命令年龄、观测年龄、动作包络及实际 Δt。候选扩展为经过语义与响应核验的加速度、挡位、轮胎滑移；不把“协议有字段”当作“本机已验证可用”。

下一模型建议数值历史覆盖约 0.5 秒，以 6 个有时间和 mask 的因果槽构造固定窗口。窗口主要帮助区分起步、制动、转向响应与动作延迟；是否扩大到 1 秒由预测残差和闭环失误决定。已有观测历史版本可先保持，扩展另建契约。对缺失槽显式遮蔽，不能把零当作真实状态。

所有动作历史只包含决策前已经执行的动作。车辆响应遥测与发送命令分别保存，不能将 Data Out 的 Steer 数值直接当作摇杆动作。世界坐标、全局赛程索引不进入首个 Actor；道路导航与可选局部参考单独编码，参考输入缺省必须在训练中出现。

时间历史长度与前方道路的预览距离是两回事。高速阶段需要足以支持提前制动的道路信息；可选局部参考提供前方弯道走向与距离，不绑定示范速度。无参考条件下，视野外的弯道可能不可知，不能要求短历史凭空补全；分别评估两种条件，并依据可见范围与实测制动能力扩展速度。

## 4. 具体模型

以下为新候选配置，不要求修改已冻结 BC 权重。

| 模块 | 推荐起点 | 职责 |
| --- | --- | --- |
| 每帧视觉编码 | 共享 ImageNet 预训练 ResNet-18，移除分类头；保留 3×5 空间网格并投影到 256 维 | 表示前方路形和导航的空间关系 |
| 视觉时间融合 | 三帧特征按时间拼接，附 Δt／age／mask，经小 MLP | 利用运动与图像新鲜度，不持有跨回合隐状态 |
| 车辆／动作历史 | 固定窗口数值经 128 维 MLP | 表示当前运动及近期控制响应 |
| 可选参考 | 有 mask 的有序车体坐标航点，64 维分支 | 表示局部路线先验，不限定最优赛车线 |
| 联合表征 | 两层 256 维 MLP，适量 LayerNorm | 融合视觉、状态与导航信息 |
| Actor | 独立两层 256 维 MLP，输出两维 tanh Gaussian 的均值与尺度；冻结评估采用确定性均值映射 | 转向、油门／刹车 |
| Critic | 两个独立 Q 头，各两层 256 维；含目标网络 | 评估观测与实际命令的长期价值 |
| 后续辅助头 | 小 MLP，接受共享状态表征、动作及持续时间 | 预测短期速度、角速度、滑移或位移变化 |

选择 ResNet-18 是为了以成熟、可微调的视觉特征作为起点，而不是把少量游戏样本全部用于从零学习视觉。官方分类模型约 11.7M 参数；本候选去掉分类头并增加融合模块，实际参数量另算。预训练没有驾驶能力保证，必须与现有小 CNN 在相同数据上比较。[Torchvision 官方模型与预处理](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html)

首轮不用长序列 Transformer、持续 GRU 隐状态或显式光流。固定窗口便于因果重建、重开清空和精确回放；若导航遮挡或动态对手需要更长记忆，再以序列数据、burn-in 和重开边界验收 GRU。

### 编码器与梯度

1. BC 初期冻结预训练主干，训练投影、融合与动作层；保留 ImageNet 通道归一化，BatchNorm 统计保持冻结。若训练与独立留出都欠拟合，可在 BC 阶段以小学习率解冻最后一个残差块；若过拟合，先补覆盖与改进增强。
2. 转 RL 的 Critic 预热期间，冻结 Actor 的**整个模型**，包括 Learner 中它所使用的共享编码器与归一化状态，仅训练价值头。不能只冻结动作头，却让共享编码器更新悄悄改变驾驶行为。
3. Learner 中共享观测编码器由 Critic 损失更新；增加辅助任务后再加入辅助损失。Actor 更新时在共享表征处停止梯度，专门优化动作选择；各参数只归属一个明确的优化器。目标 Critic 包括目标编码器。
4. 逐步解冻视觉层，避免微小、强相关的样本立即改坏预训练特征。保留原始数值像素；特征缓存必须绑定编码器版本，不能将旧 latent 当作新编码器输入。

视觉控制文献支持研究这种梯度分工和图像增强，但不是本组合在 FH5 已有效的证据。DrQ-v2 实际采用 DDPG 式算法；这里仅借鉴其编码器与增强处理，不能把本方案称为 DrQ-v2。[SAC+AE 作者代码](https://github.com/denisyarats/pytorch_sac_ae/blob/master/sac_ae.py)、[DrQ-v2 作者实现](https://github.com/facebookresearch/drqv2)

## 5. 动作契约必须先于 RL 固定

策略继续直接决定双轴连续动作，不增加永久的传统控制器小残差限制。临时实验包络只限定当前可验证范围，后续依据驾驶证据扩大。

推荐在输出分布中就表达可执行区间：由当前幅度范围、上一条发送命令与实际 Δt 计算动作区间，再由 tanh 和仿射映射产生命令。Q 训练使用实际发送的命令，Actor 更新及目标 Q 的后继动作都使用同一映射规则。采用命令坐标下的密度时，log-prob 包含 tanh 与仿射变换的 Jacobian，温度 α 的目标熵也按同一坐标及当前区间换算，不能无说明沿用归一化两轴的默认值。包络及变化率约束属于可见状态和版本配置，不能在末端大幅裁剪后仍把原始提议当作已经执行的动作。

区间为空或退化到单点时，不构造虚假的连续分布密度，交给明确的保持／停止规则并记录控制归属边界。后继状态是否可 bootstrap 要结合真实任务终止或故障处理；不能在 SAC target 中计算不存在的连续 log-prob，也不能一律伪造零价值终止。BC 转 SAC 时先核对关闭探索后的映射命令与 BC 一致，再启用窄分布探索；不能只复制权重而忽略动作缩放变化。

保留提议、映射后命令、成功发送和遥测响应四层日志。发送成功不证明游戏已经采用，也不直接给出游戏内部的生效时刻；接口响应仍需校验，命令历史负责保留延迟线索。过期动作不发送、不续租。用户停止、监督器接管或接口故障明确切断控制归属；未发送的提议不能制造训练转移。若一个采样间隔发生多次命令变化，记录动作时间线；首版一步训练只纳入动作保持语义清楚的区间。

现有人工示范超出实验包络的部分不能简单裁剪标签，再配上原来高速行驶的下一状态。它们可留作其他范围的经验或辅助预测；进入当前 BC／Q 批次前须检查动作与条件兼容。

当前死区测量只有粗粒度依据。起步和转向需要真实响应校验；不要随意添加最小油门或不连续转向跳变来掩盖策略问题。必要的设备校准映射独立版本化，并保持采样与训练语义一致。

## 6. 训练：先有可用起点，再自主改进

### A. 获得真正能驾驶的 BC 起点

先完成数值图像与 DXGI／时间契约，核对实体手柄记录，并在大规模采集前确定分辨率和预处理配置。随后使用独立脚本重新采集多圈正常驾驶，包含起步、松油、LT 制动和转向，不只修补旧的极小示范集；编码及容错推理工作继续并行。对起步失败分别检查初始挡位、历史零值、输出分布、死区及覆盖，不要求用户无转向地反复踩油门。

采集固定运行版本，完整数据块封存后以不可变清单供训练读取。建议 3–5 次完整正常跑圈作为首批检查点，按质量、行为覆盖、独立留出和真实 BC 表现决定补充；这不是最低开训配额或足量保证。多圈数据不替代自主学习的奖励、重开和评估条件。具体版本隔离、故障边界及就绪规则见[持续采集方案](demonstration-collection-plan.md)。

训练按独立录制切分；停车、起步、转向、制动、正常恢复分别检查。轻微亮度和小平移增强需保持三帧一致；先避免改变导航线颜色或大幅裁掉远方道路。离线动作误差和黑图干预只作诊断。

可见验收先是原车在已有核实区域自主起步、有实际转向响应并停车；随后在扩展的已核实路段通过弯道。候选须从独立重开重复运行，不用一次偶然移动作为可靠驾驶证据。

当前约 19.55 米核实范围主要为直线，首次可证明起步和方向修正，不据此宣称已经会过弯。短段结束时由既有停止流程刹车，只计作实验正常结束；必须分开报告策略自身减速与监督器停车，不能把后者当作模型学会制动。

### B. 从 BC 进入普通双 Q SAC

选择普通 SAC 作为第一个 RL 基线；QR-SAC 后置为有明确价值估计问题时的对照。Off-policy 重放符合单游戏实例采样昂贵的条件。GT Sophy 的成绩支持研究连续动作 RL，但其专用 API 和并行采样条件不在本机复现。[SAC](https://arxiv.org/abs/1812.05905)、[GT Sophy 核查](gt-sophy-2022-research.md)

- 用可驾驶 BC 的确定性行为和经过标定的小幅探索采集初始在线经验，不采用库默认的全范围随机 warmup。
- 单独初始化双 Critic，以真实、完整且有可靠奖励、终止／截断及命令记录的数据进行有限预热；冻结整个 BC Actor。只有动作标签的示范不自动具备 Q 学习所需信息；只观察到 BC loss 下降不表示已经有可用价值函数。
- 确认价值与实际回报尺度可解释、更新未发散后，低学习率放开 Actor。保留短期 BC 正则帮助交接，按独立驾驶表现衰减至零；示范留在 Q 的经验池不等于永久模仿。
- 冻结预热不能保证平稳过渡，候选仍可能退步。出现退化时保留可靠版本，诊断数据、Critic 和探索强度，不靠更大的正则永久锁死策略。

旧数据帮助在线学习有研究依据，但本项目没有 RLPD 的完整配方，也没有 WSRL 所假设的已训练离线 Q；仅借鉴相应经验，不能宣称照搬即能达到论文效果。[RLPD](https://arxiv.org/abs/2302.02948)、[WSRL](https://arxiv.org/abs/2412.07762)

首轮参数候选：batch 32，Critic 学习率 1e-4、Actor 3e-5；主干解冻时 1e-5 起；软更新系数 0.005；每新增有效转移最多一次 Critic 更新，Actor 每两次 Critic 更新一次。数据与显存允许后再增 batch，不首先追求高更新比。固定权重尺度、随机种子和配置，参数依短段对照调整，数值不代表论文最优设置。

### C. 经验分布与时间

在线真实经验为主，初始可试 25% 兼容示范与 75% 在线经验；示范量极少时避免反复采同几个样本。在线池保留近期探索与旧技能记录，区分回合、速度、动作、成功／失败与控制归属。完整失败可训练价值；损坏像素、无法配对的动作或跨重开样本不训练。

先用一步 SAC 便于审计实际动作和延迟。变步长记录保存有效动作持续时间，折扣按固定物理时基调整，例如 γ(Δt)=γ0^(Δt/Δt0)，时间成本也按真实时长计算；Δt0 与 γ0 属于任务版本。若接口中断导致没有真实最终观测，不能用重置状态 bootstrap。之后再单独对照多步回报。

任务本身的完成／失败才是终止；单纯录制窗口结束是外部截断，有可信末状态时仍需 bootstrap。若训练任务明确规定有限截止时间，则把剩余时间加入任务状态，超时才可按该任务定义处理。30 秒录制结束不表示整圈未来价值归零。[Gymnasium 时间边界说明](https://gymnasium.farama.org/main/tutorials/handling_time_limits/)

未来标签来自实际经历，不要求人工逐帧标注。示范数据、在线经验和冻结评估集的用途分别管理；正式评估结果不能又拿来选模型又称为未见过的最终测试。

## 7. 辅助预测：学车辆响应，不模仿路线

在首次真实闭环之后启动。第一组优先预测下一有效控制间隔的纵向／横向速度变化与横摆角速度变化；滑移在字段验证后加入，短期车体位移作为可选项。用起始观测、**实际执行动作及持续时间**预测随后实测结果，目标采用归一化的增量与 mask。

短期建议从相邻有效状态转移开始，再尝试 0.2／0.5 秒预测；多步需要期间的实际动作序列，不能把示范者后来多次转向的结果归因于当前一个动作。训练分支可读取后来执行的动作作条件，当前 Actor 输入只能读取当时已知历史，防止动作标签泄漏。

损失先用 Huber/SmoothL1，并在留出回合上与“速度保持不变”“局部线性外推”等简单基线比较。权重从小值开始，以共享特征的梯度规模和闭环收益调节，避免状态预测压过控制任务。固定车首先学习本车在不同速度和工况下的响应；不急于加入车辆 ID 或多车型适配网络。

其作用来自辅助损失对共享编码器的训练：让同样的视觉、速度和近期操作形成更能解释车辆响应的表征，再由 RL 学习如何利用它。未来预测辅助表征有公开研究依据；这里的低维遥测目标是本项目建议，不是直接复刻其标签。[SPR](https://arxiv.org/abs/2007.05929)

不首先预测整张未来图像，不要求输出“最优航点”。这些辅助头主要训练表征，Actor 无须等它们显式产出才能执行；它们可在诊断中显示，也可在证明价值后加入控制。沿真实记录预测准确，不代表对未尝试动作也准确；未来若做 MPC／想象 rollout，要增加反事实与误差累积验证。

## 8. 自动驾驶与自主学习的运行组织

采用四个职责清晰的执行部分：采集／预处理、冻结 Actor 推理、动作监督与任务管理、Learner／评估调度。录像和外部仪表盘为旁路订阅，不参与关键控制等待。

推理模型在一个尝试内保持冻结。Learner 在另一份参数上更新，生成带完整编码器和归一化状态的快照，优先在尝试边界原子换版；旧推理结果、旧 epoch 和旧模型特征缓存不得混用。训练候选可以探索，但可靠默认版只在独立评估通过后替换。

运行顺序为：已核实起点 → 采集／推理／执行 → 完成或真实失败 → 保存前向经验 → 有界重开／恢复 → 更新候选 → 冻结评估 → 晋升或继续探索。重开未验收时只能称受监督短段实验；自动循环需先通过重复重开。普通 FH5 不假设可传送至任意弯道；倒带是独立恢复能力，动画不进入驾驶 replay。

短段到全程采用可到达场景的渐进扩展，保留旧技能复测。增加速度、探索幅度或路段时分别记录配置；覆盖范围与奖励可信度同步增长，不用单条轨迹虚构整圈道路宽度。对抗后续再加入可见车辆的时序跟踪、盲区处理和相对运动特征，先有对手完赛，再争名次。

## 9. 奖励与晋升

训练奖励以已确认的合法新增进度、实际耗时、完成／失败和已确认违规为主。适度约束无效动作振荡；滑移是车辆状态线索，不能把所有侧滑一律视为错误。人类线路距离、车速读数和“预测得像不像示范”不作为最终驾驶目标。

任务状态要足以解释奖励：例如离历史最远合法进度的相对差、剩余任务时间，以及动作包络。可只向 Critic 提供当时可得的评分上下文，Actor 仍不取得全局路线记忆或未来信息；不能虚构训练时可得的精确道路／对手状态。上下文与使用条件写进回放契约。

奖励上线前用停车、往返刷进度、早撞、漏点、持续蹭墙和倒带反例检查整段回报排序。遥测突变不自动当作碰撞；依据不足的事件保留为未知，限制该运行晋升。详细有效性与终止／截断规则沿用[专项设计](reward-and-validity-design.md)。

晋升分开报告：所有尝试中的有效完成率、有效用时分布、接管／恢复、违规与未知事件、控制平顺性和接口故障。先保持可靠性，再比较速度；保留激进候选但不因单次最快就替换默认版。有限样本的可靠性结论保持对应尺度，RL reward 或辅助预测 loss 不替代驾驶评估。

## 10. 实时性与资源预算

控制先以 10 Hz 建立可比较闭环，再在共享 GPU 实测支持时升到 20 Hz。DXGI 可独立以 60 Hz 为采集候选，预处理 30–60 Hz；这些均是预算起点，不是本机已达标结果。最新帧源时间到动作发送的 P95≤75 ms、P99≤120 ms 沿用[管线方案](image-pipeline-research.md)的初始目标，不能把发送返回当作游戏实际响应时间。

缺帧跳过决策，命令租期不刷新；控制时效与存档完整性分别处理。沿用当前已验证的动作到期上限，不因训练变慢放宽；更高速驾驶需要另行验证响应和停止距离。

4090 同时渲染与训练时，独立进程不等于独占算力。Learner 使用小 batch／microbatch，在任务边界让出资源；测量游戏帧时间和控制尾延迟，超预算先降低训练频率，必要时在重开／评估间隙交替训练。在线学习指持续从新经验更新，不要求每毫秒同时渲染、反向传播和控制。

首个自动循环推荐先交替进行冻结策略采样和有限批学习；共享 GPU 的实测时效通过后再并行。持续运行报告每小时有效运动秒数、有效转移、重开成功率和覆盖场景，不能用 GPU 利用率代替学习效率。

存储按唯一数值帧预算，不为每个转移复制三张历史图。480×270 RGB uint8 每帧 388,800 字节；10／20 个唯一帧每秒约 13.0／26.1 GiB 每小时，未计元数据且不假定压缩率。30 Hz 预处理帧若全部存档约 39.1 GiB 每小时。仅决策引用帧的实际去重率需记录，不保证刚好等于决策频率。

建议先给热图像缓存设置 8 GiB 上限，转移存帧引用，较旧数据在本地 SSD 用可精确重建数值像素的格式存储；写盘异步且有界。淘汰帧时同时检查引用转移，不能留下悬空训练样本。仅 latent 模式限于编码器确实冻结且版本匹配的阶段。磁盘／记录缺口可影响哪些经验能学习，但不允许存档堵塞驾驶。

## 11. 实施顺序与选择依据

| 阶段 | 下一项可见成果 | 进入下一阶段的依据 |
| --- | --- | --- |
| P0：当前前沿 | #33 数值回放 → #34 DXGI 与 #35 Δt BC → #36 容错推理 | 数值、时间、动作与资源记录可信 |
| P1：真正驾驶 | #9 在核实区域起步、实际转向、停车；再逐步通过弯道 | 从独立重开重复运行，不能用注入油门代替模型能力 |
| P2：自动采样 | #10 及既有重开任务，冻结驾驶的重复评估和完整失败记录 | 能有界重开并产生可训练的真实转移 |
| P3：首次 RL | #11 使用可驾驶 BC 初始化 SAC，展示候选与冻结 BC 的同条件结果 | 值函数、探索和实际驾驶均可解释，保留无改善结果 |
| P4：状态理解与长期改进 | 动力学辅助头、弱项回放、续训、扩大路段和速度 | 辅助预测与闭环增益独立验证，持续保留旧技能 |
| P5：全程与对抗 | 无接管无倒带歌利亚，随后有车完赛与竞争名次 | 全程规则有效，车辆交互信息可用 |

P4 可以与 P2/P3 的适当实验并行，但不能拖延首次驾驶或首次 SAC；辅助头是否改善性能不是进入 RL 的必经门槛。ResNet 候选可在 P0/P1 离线准备，现有小 CNN 若先达到真实驾驶验收就保留，不为架构整齐重做已通过结果。

本推荐保留一个明确基线，而非同时铺开多套算法：PPO 暂不作为默认，因为当前需要重用昂贵的真实经验；QR-SAC、GRU、世界模型和 MPC 在基线暴露具体瓶颈后分别对照。以“真实驾驶的进步”和“每小时有效经验”决定升级，不能仅凭模型更大或论文成绩选方案。

最少保留四组依次进行的对照：同数据的小 CNN／预训练 ResNet、同结构的真实 Δt／无 Δt、冻结 BC／SAC、SAC／SAC 加一个动力学辅助头。每次记录真实驾驶、控制时效和数据条件，不一次扫描所有组合。需要区分预训练与容量的贡献时再增加匹配结构对照，不把一次架构升级全部归因于预训练。

本文是研究推荐，没有改动训练代码、控制器、游戏设置或 GitHub 任务依赖。实现时把需要的新观测／模型契约与辅助任务单独拆分，不重写历史验收。
