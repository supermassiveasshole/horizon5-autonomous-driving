# FH5 自主倒带、局部重试与训练数据边界

核查日期：2026-09-28。本文只做资料核查和设计建议，没有启动游戏或验证实机倒带。范围遵循用户要求：正式成功必须无人接管、无倒带；另行探索 AI 自主倒带能力。

实现进展（2026-09-30）：[恢复监督回放](recovery.md) 已实现合成信号上的有界状态机；实机倒带、实际历史重建与驾驶恢复仍未验收，下文的游戏能力未知项保持不变。

## 结论与证据边界

自主倒带值得优先作为训练基础设施试验：目标是失败后自动回到失败前附近，重新尝试同一难点，减少反复从歌利亚起点驶来的成本。它也可以单独展示无人值守恢复能力。它不是正式无倒带驾驶成绩的一部分，更不能证明普通策略已经稳定完赛。

实现候选是普通游戏手柄/UI 操作。`vgamepad` 提供按钮按下、松开和状态更新，足以表达 UI 操作序列；其 `reset()` 只恢复手柄默认状态，不会重置游戏。[作者 API 文档](https://github.com/yannbouteiller/vgamepad)

本次能找到的官方倒带限制页明确标作 **FH4 Rewind**，提及开赛初期、对手过线等限制。这些不能直接作为 FH5 的规则；该页搜索结果可读，直接打开时重定向失败。FH5 当前版本的模式支持、可倒带长度、恢复粒度、比赛计时、检查点状态以及对手车辆是否一致恢复，均须实测。本次没有找到官方 FH5 任意存档、任意位置 reset 或精确快照恢复接口。[官方 FH4 页面，仅作为版本区分依据](https://support.forzamotorsport.net/hc/en-us/articles/360025509613-Rewind)

## 先做规则监督器

以下为拟议设计，不代表已经实现或由游戏提供。

1. **检测失败并记录原因。** 候选信号是 HUD 漏点提示、持续无有效进度、明显偏离可行驶区域。正常可恢复偏差先允许驾驶策略自行修正，避免一偏线就倒带。
2. **结束当前前向片段。** 保存最后有效观测、动作、失败标签和对应视频；释放油门、转向及按钮，暂停普通驾驶采样。
3. **请求倒带并确认 UI 状态。** 按当前游戏绑定操作，不把固定延时后继续驾驶当成成功。倒带不可用、操作超时或状态不明时，走整场重开流程。
4. **选择可用恢复点。** 尽量回到失误前且留有刹车/调整空间的位置；选择仅限游戏实际保留的历史，不能承诺精确返回某一时间戳或远处赛段。
5. **确认恢复并重建状态。** 用画面、遥测新鲜度、位置与前向运动确认恢复。清空动作队列、PID 积分、差分滤波器、帧堆叠及循环网络隐藏态；从新片段积累必要历史。
6. **重新尝试。** 每个难点设有限重试次数和超时。记录失败类型、倒带耗时、恢复位置、重试成功率；持续失败时整场重开或切换训练任务。

这个规则监督器本身就满足“系统会自主倒带”的第一层能力。只有稳定收集到恢复数据后，才值得训练高层策略选择“自行救车、倒带重试、整场重开”和倒带深度；没有必要先让 RL 学习菜单按键。

## 学习数据必须沿前向时间成立

Gymnasium 区分任务内终止 `terminated` 与外部截断 `truncated`，两者影响价值函数是否 bootstrap。将以下处理应用于 FH5 是本项目设计，而不是 Gymnasium 自动解决游戏重置。[官方终止/截断说明](https://gymnasium.farama.org/main/tutorials/handling_time_limits/)

| 情况 | 驾驶经验处理 |
|---|---|
| 已达到定义好的驾驶失败条件 | 保留真实失败前向 transition，标 `terminated=True`；不因后续倒带抹去失败代价 |
| 监督器提前结束仍可继续的片段 | 标 `truncated=True`；需要 bootstrap 时只能使用截断前的有效最终观测 |
| 遥测丢失，无法确定动作对应的后继状态 | 标记数据缺口，舍弃无法构造的 transition；不能拿倒带后的状态补齐 |
| 倒带动画、菜单操作、恢复瞬间的位置跳变 | 保留诊断日志，不进入普通驾驶 replay buffer |
| 已确认恢复后的再次行驶 | 新 `segment_id`，正常积累前向经验；不得与旧片段拼接 n-step return 或循环序列 |

保留 `run_id / attempt_id / segment_id / parent_segment_id / rewind_reason`，使一个失败和多个重试可关联、可重放。训练中同一弯道的重试可产生有效学习样本，但重复练习的前进量不能累加成全程完成度，也不能被当作相互独立的完整赛程评估。

训练奖励使用片段内合法路线进度、时间成本、失败代价及适量平滑项。若以后高层策略也能选倒带，高层应计算真实墙钟耗时和重试成本，并避免通过“驶过一段—倒带—再驶过”反复领取任务进度奖励。低层无倒带驾驶策略的经验与高层恢复决策经验分别定义。

倒带后先清空历史最容易验证；未来若要恢复循环网络状态，必须同时证明游戏状态和网络历史在同一时点一致恢复，不能仅恢复车辆坐标就恢复旧隐藏态。

## 可验收里程碑

以下次数是首轮建议测试规模，不是游戏能力声明或可靠性保证。

| 里程碑 | 可见结果与通过条件 |
|---|---|
| R0：倒带可用性矩阵 | 在选定空场模式，验证正常行驶、起跑附近、漏点/撞车和终点附近的操作；记录可用性、UI、遥测及时间变化 |
| R1：自动重试闭环 | 在实际可到达的短弯道累计做 20 次恢复测试；逐次报告成功/失败、耗时与失败原因，失败必须有整场重开或停止路径 |
| R2：学习一个难点 | 同一弯道失败后自动倒带、重试并采样；对比训练前后的独立无倒带通过率、用时和控制平滑度 |
| R3：全程两套报告 | 正式评估报告无接管、无倒带的完赛率与用时；恢复演示报告自动倒带次数、真实总耗时和辅助完赛率 |

课程学习先使用真实可创建、可重开的短赛段；歌利亚深处的难点可由基线策略正常驶入，再利用仍在游戏倒带历史内的局部窗口重复练习。不能承诺任意抽取歌利亚位置启动 episode。每轮训练后仍需从正式起点进行独立无倒带评估，以检测局部重试带来的起始状态偏差。

有对手阶段需要重新核查恢复语义：比赛时钟、对手相对状态、检查点和碰撞后状态是否恢复到一致场景目前未知。即使视觉上回到相近位置，也不能声称这是同一随机种子、同一完整世界状态的确定性对照实验。
