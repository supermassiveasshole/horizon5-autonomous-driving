# T01：遥测录制与离线回放

对应 [Issue #2](https://github.com/supermassiveasshole/horizon5-autonomous-driving/issues/2)。运行命令见 [README](../README.md)。本切片建立人工驾驶数据的可观察链路，后续控制和学习通过同一个实验入口扩展。

## 输入与配置

`fh5 record` 默认绑定本机 `127.0.0.1:5300`，`--seconds` 指定接收时长。配置 `schema_version` 为 `1`；`control_source` 只接受 `human` 或 `unknown`。

`snapshot` 必须有 `vehicle`、`variant`、`tune`、`assists`、`event`、`environment` 六项。每项包含文本或空值 `value`，以及 `status`：

| 状态 | 含义 |
|---|---|
| `unverified` | 尚未核实，可以保留 `null` |
| `user_reported` | 用户提供，尚未独立核对 |
| `verified` | 已核对；必须同时填写非空值和 `evidence` 依据 |

例如调校可以记录调校名称、分享代码或配置截图路径；辅助应包含换挡方式及各项辅助状态。依据文件需与该次记录一同保存，程序只检查字段完整性，不验证依据真实性。车型版本不能根据用户说“第六元素”猜测。遥测中的 `CarOrdinal`、等级、PI 单独保留，不覆盖快照。

设置位置也可参考 [MOZA 的 FH4/FH5 遥测配置说明](https://support.mozaracing.com/en/support/solutions/articles/70000625637-forza-horizon-4-5-telemetry-configuration)；本项目使用上述本机 IP 和端口。

## 文件与时间

每次运行写入新目录：

| 文件 | 内容 |
|---|---|
| `session.json` | 格式/解析器/诊断版本、来源、配置快照、开始/结束 UTC、录制状态 |
| `packets.jsonl` | 每行一个原始数据报的十六进制内容、接收端单调时钟 ns、接收 UTC |
| `report.json` | 从原始记录重建的样本、诊断事件、汇总和元数据 |
| `report.html` | 自包含报告，可播放、定位样本、检查轨迹与车速 |

原始包逐行刷新；Ctrl+C 会保存中断状态并生成报告。进程被强制结束或磁盘写入失败时不保证最终报告生成，可对已有记录单独运行 `replay`。回放保留源文件；损坏行会产生事件并跳过，末尾未完成行单独标记。元数据版本不兼容时明确报错，不猜测解析。

`received_monotonic_ns` 是接收程序取到数据报后的时钟值，不能当作游戏发送时间或跨进程同步依据。`received_utc` 用于人工对照。游戏 `TimestampMS` 为包内 uint32 毫秒计时；三个时间各自保存。播放与 `receive_span_seconds` 累加有效样本之间的非负接收间隔，包含中途等待，不等于游戏圈速或完整录制窗口。

`source_kind=udp` 仅说明经 UDP 接收；合成输入为 `synthetic`。`game_validation` 始终为 `unverified`，实机核验由另存的证据记录承担。包格式有效、录制完成和驾驶有效是不同概念。

## 解析与诊断依据

当前支持 FH5 的 324 字节 Dash 布局，参考版本固定为 [go-forza-telemetry v1.2.0 的 v2.go](https://github.com/csutorasa/go-forza-telemetry/blob/v1.2.0/v2.go)。这是社区实现依据，偏移、单位和游戏行为仍须用本机实录交叉核验。

- 游戏时间、活动标志、世界 XYZ、m/s 车速、车辆编号/等级/PI 是解码字段；km/h 为推导值。
- 保留整个原始包，尚未解码的字段可以后续提取。其他长度作为异常保留，不套用 FM7 的不同布局。
- `telemetry_controls` 是游戏输出的原始踏板/转向字段；`command=null`。本切片没有发送驾驶命令，也没有建立动作校准或同步标签。
- 回放的“减速刹车”来自 `telemetry_controls.brake`（Dash 包的 `Brake` 字段，0–255），表示普通行车制动，通常对应手柄 LT；它不是手刹，也不是实测减速度。手刹目前没有单独解码/显示，完整原始包仍保留。
- 超过 0.5 s 的接收间隔标记 `receive_gap`；程序不会猜测精确丢包数。UDP 录制保存起止单调时钟，检查录制开始至首包及末包至结束的静默。合成数据与早期缺少起止时钟的记录只检查相邻包；完全没有有效数据另行报错。
- 相邻位置位移超过 `20 m + 200 m/s × 接收间隔` 标记 `position_jump`。这是粗略诊断，不能证明倒带、碰撞或离路。
- 游戏计时倒退、uint32 回绕、接收时钟不递增、`IsRaceOn` 变化分别记录；`IsRaceOn` 不能作为起跑、完赛或倒带证据。
- 异常边界断开轨迹，未知包、非有限字段和损坏行保留在原始文件中。诊断阈值及版本写入元数据。

报告使用世界 X/Z 投影，方向尚未实机标定，不包含道路边界或地图。轨迹仅绘制活动状态的位置，所有非活动包仍保留在原始记录与回放样本中；活动状态切换本身不会被当作驾驶位置跳变。它一次加载整份记录，先用于短段接入验证；长时间采样的容量与吞吐验收属于后续任务。

### 运动字段增量（T25）

当前解析器为 `fh5-dash-324-v2`，新增 yaw、车体速度与角速度，见[观测契约](observations.md)。原始格式仍为 v1；旧 `fh5-dash-324-v1` 录制继续可回放，并在结果中记录 `analysis_decoder_version`，不改写源文件。普通遥测录制/回放仍只需标准库；`observe` 的像素完整性检查需要 Pillow（`events` extra）。T25 已交叉核验水平航向约定，尚无完整 3D 或相机外参标定。

## 返回码

| 返回码 | 含义 |
|---|---|
| `0` | 操作完成且至少有一个可解码样本；仍需检查报告中的异常 |
| `2` | 配置、文件、版本或接收错误 |
| `3` | 操作结束但没有有效遥测 |
| `130` | 用户用 Ctrl+C 停止录制，已尝试保存可回放记录 |

回放中断过的记录不会返回 `130`，但报告保留原中断状态。

## 验证记录与实机验收

本机各次实际检查及接入尝试见 [T01 验证记录](validation/t01-recording.md)。

2026-09-28：自动化测试使用合成包，覆盖录制/回放一致性、真实本机 UDP 传输、接收中断、未知格式、非有限字段、断流、位置/时钟跳变、暂停/恢复、损坏记录恢复、配置证据要求、输出保护和空录制。另用合成演示在浏览器检查回放交互。这些检查本身不构成 FH5 实机通过；同日第二次实录另行获得活动驾驶片段，接入与回放结果见上述验证记录。字段精确标定、调校和辅助核对仍待完成。

实机验收按以下步骤补齐：

1. 保存本次配置、游戏/平台版本、Data Out 设置依据及使用的 Git 提交号。未确认项目保留待核实。
2. 启动一分钟录制，人工完成静止、加速、转弯、刹停；短暂暂停后恢复，保留全部数据。
3. 对照游戏画面确认车速量级、踏板/转向变化、暂停状态及车辆编号/PI。记录时间同步和轨迹方向是否符合观察，不能仅凭包长宣告通过。
4. 结束后关闭接收端，运行离线回放，核对原始记录和回放摘要；保留 HTML/JSON、画面或观察笔记及异常。
5. 将实测结果与软件检查分别记录，再决定是否满足 T01。游戏接入通过不代表已能自动驾驶或适合训练。
