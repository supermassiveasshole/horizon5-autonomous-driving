# SAC 中断与续训（T12 / #13）

当前支持合成经验上的真实 CPU Torch 训练状态恢复，通过 `run_experiment(SACResume(...))` 或 CLI 继续已有 SAC 阶段。它恢复学习进度，不恢复游戏位置或驾驶尝试，也不证明 FH5 轨迹可重复。自动采样循环、实机重新入场和完整在线经验扩充仍需后续接入；#13 保持开放。

跨进程停止、移动快照续训及连续训练对照见[本次验证记录](validation/t12-sac-resume.md)。

## 使用

```powershell
uv run --locked fh5 sac-train --config configs/sac-learning.example.json --output runs/sac-001
uv run --locked fh5 sac-resume --checkpoint runs/sac-001 --output runs/sac-002 --steps 100
```

`--steps` 是本次追加更新数，范围 0–10000；累计计数上限 100 万。输出须为源模型和经验目录以外的新目录。续训沿用冻结的学习率、batch、actor 更新间隔、动作包络和模型配置，不接受隐式覆盖；`--steps 0` 可核验恢复并导出新快照。

训练开始后，在输出目录新建 `stop.request` 可请求停止。当前一次完整 critic/actor/温度及目标网络更新结束后才检查下一次请求，保存可恢复状态并返回退出码 4。正常完成预算返回 0，输入错误返回 2。Python 调用可通过实验入口的 `sac_stop_requested(completed)` 提供外部停止信号；参数为累计已完成更新数。

这是更新边界的协作式停止，不会抢占正在执行的 Torch 操作。不在梯度或优化器更新中间保存状态；强杀进程或异常退出后，最后一个完整快照仍可用，未封存目录不能恢复。首次运行尚无完整快照时，强杀不能保住中间更新。

## 恢复范围

恢复图像/状态编码器、策略头、双 Q、目标编码器/双 Q、各优化器状态、温度、CPU 随机状态和累计步数。actor 每两次 critic 更新一次的相位跨保存保持，续训不会重跑 BC 或 Q 预热。共享特征仍按当前编码器重新计算，不携带旧 latent。

新输出使用版本 2：

- `policy.pt` 保存完整学习状态；`policy.json` 绑定权重、配置、状态摘要、经验和初始化 BC。
- `experience/replay.json` 与所引用原始 RGB 字节一并复制，保留帧间 Δt、时间质量、动作保持、任务状态、终止及奖励字段；不重新打时间戳或编码为 JPEG。
- `bc/` 保存初始化模型及像素/归一化/参考/历史契约，不依赖工作区里的旧路径。
- `training-report.json` 绑定本段更新记录；`history/` 保留祖先清单与训练报告，原候选目录不会覆盖或删除。祖先权重仍位于各自候选目录，回退时须保留这些原候选。
- `resume_contract` 明确当前 SAC 阶段、优化器归属、CPU/Torch 版本、两线程和确定性设置。当前未采用动力学辅助头和模仿衰减调度，不能把这些缺省解释成已完成对应功能。

每个候选封存自己的数值经验；恢复只使用完全相同的经验与契约。新在线经验的追加和兼容审查属于下一步采样循环，不可直接改旧 replay。旧版本 1 候选仍可冻结回放，但缺少封存经验及训练历史，当前明确拒绝续训，不静默升级旧结果。

## 校验与边界

恢复前校验权重、清单、报告和历史摘要，随后重建并校验每份所需数值输入。缺图、坏像素、改时间、动作保持、奖励、历史、输入维度或包络都不能静默恢复成另一个条件。损坏输入不生成可发布的新候选；目录可能保留失败前的诊断文件，只有最后写出的有效 `policy.json` 标记完整快照。

单份权重上限 256 MiB，经验清单 128 MiB，封存帧累计 512 MiB，历史报告累计 128 MiB 且最多 1000 段；训练沿用原图像 batch 与缓存上限。这些是分别的资源界限，不表示总内存只有其中一项大小。CPU 同环境的连续/分段状态可以逐项比较；跨 Torch 版本不自动迁移，不据此保证跨硬件位级一致。

续训不连接采集或控制设备，不继承上一游戏 epoch、动作租期或当前帧缓存。未来重新进入游戏必须重新验证起点并开始新尝试，不能把中断两侧当成连续驾驶转移。
