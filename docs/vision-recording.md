# 彩色观测录制与回放（T22）

从实验入口录制 RGB 画面和 UDP 遥测，无控制器、菜单输入或驾驶输入。此模块提供后续道路感知的数据；不识别道路，不输出米制边界，不证明驾驶能力。

## 运行

Windows 上安装可选截图依赖，确认 Data Out 为 `127.0.0.1:5300`，手动选择追尾远视角。固定档位并避免自由观察，仍允许游戏随速度调整相机距离。配置快照填写实际条件，不能仅凭复用旧配置认为条件已重新核验。

```powershell
uv sync --locked --extra events
uv run --locked fh5 vision --config configs/goliath-fixed-v2.json --output runs/vision-001 --camera chase-far --seconds 60
uv run --locked fh5 replay runs/vision-001 --report runs/vision-001/replay.html
```

`--camera chase-far` 是操作者声明，不是视觉识别结果。仅抓取前台 FH5 客户区；切出游戏后暂停截图，继续记录遥测与焦点变化。F8、Ctrl+C、时限或在输出目录创建 `STOP` 文件均可结束。输出目录必须不存在。

默认输出 960×540、RGB JPEG（质量 90，无色度子采样，有损）；先整数面积缩小，尺寸仍不匹配时再双线性缩放，实际方法与原客户区尺寸逐帧保存。相比首轮 RGB PNG 探测，减少编码和存储开销，保留颜色和明确的编码条件。不能据此假定处理频率已经达到目标。

参数：`--period 0.1`（目标 10 Hz）、`--max-age-ms 100`（观测年龄阈值）、`--max-mib 256`（采集预算）。时限 0.1–600 秒、周期 0.05–5 秒；如机器负载使 10 Hz 不稳定，可显式用 `--period 0.2` 重测并按 5 Hz 报告。不会隐藏降频。

## 数据与时序

- `packets.jsonl`、`session.json`：兼容原遥测记录和诊断；坏包、暂停、接收断流、游戏时间回退及位置跳变产生断点。
- `frames/`、`vision.jsonl`：图片及捕获 UTC、单调时钟开始/结束、编码后可用、交付与写盘后时间，原图/输出尺寸、RGB、缩放、编码参数、SHA-256；焦点切换、队列丢帧与错过采集周期单独记录。
- `vision-config.json`：原始配置字节快照；`vision-session.json`：格式版本、代码文件哈希、相机声明、阈值、停止原因、资源释放结果、原始包/图像日志/配置哈希。
- `report.html` 和同名 JSON：彩色逐帧/播放、当时已收到的遥测、事件、完整性问题和时序分布。HTML 离线引用原 `frames/`；同盘使用相对路径，跨盘使用绝对文件 URI。移动时保留对应路径；不是单文件图像归档。

在线候选取**编码画面可用时已收到的最新包**，保留包索引、接收时间、游戏时间与片段号。截图开始前也必须有同一连续活动片段的近期包；期间有焦点/遥测断点，或画面/遥测过旧，均标为不可用于驾驶。年龄同时检查编码完成与交付到实验入口的时刻，不能把排队的旧图片算作新输入。图片或遥测缺失时只保留实际存在的数据。

`posthoc_after_capture` 单独保存截图结束后第一个同片段的近期包，可能晚于画面可用时间，**不能输入在线策略**。不存在插值、跨片段拼接或把旧帧重新打上新时刻。接收时钟对齐不能证明物理引擎、渲染和 UDP 数据同步；该模块还未接入策略决策时钟。

## 上限与故障

UDP 队列最多 4096 包，图片队列最多 2 帧，事件队列最多 128 条；图片排队溢出留下丢帧事件，遥测/事件溢出终止记录。单次原生截图/初始化超过 2 秒会终止消费，最多等待各工作线程 0.5 秒退出。若原生调用卡死，报告资源未释放；该线程隔离至进程结束，不冒称已经清理。

采集预算对原始包、编码图片及日志计入保守字节估算，达到预算前停止。另有配置、清单和派生报告开销；CLI 开始前要求预算之外至少留出 128 MiB。已写文件不因后续失败而删除。日志截断或文件哈希错误可回放诊断，但受影响观测不作为驾驶输入。哈希用于追溯和发现意外变更，不提供真实性认证。

报告同时给出截图耗时、编码后可用延迟、保存延迟、帧间隔和 UDP 接收间隔的中位数/p95/最大值。连续频率排除已检测的观测断点，`wall_hz` 包含等待和切出游戏；不能混用两者，也不能把接收抖动直接归因于截图而缺少独立对照。

历史纯遥测记录继续使用原回放方式；导入此模块不会加载 MSS、Pillow 或虚拟手柄驱动。软件验证通过 `run_experiment`，覆盖因果配对、异常分段、缺失观测、停止预算、损坏日志和真实 loopback UDP；实机结果另记于验证文档。
