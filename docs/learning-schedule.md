# 采集优先的 BC 训练调度（T36 / #38）

`collection-bc-train` 在固定数值快照上运行现有 Δt BC。它只读取指定采集进程和主机资源，不启动游戏、停止采集或取得驾驶控制权。软件调度已具备；真实 4K 游戏/训练共存预算尚未验证，示例阈值是候选配置。

```powershell
uv run --locked fh5 collection-bc-train --config configs/collection-learning.example.json --output runs/scheduled-candidate-001
```

将示例中的路径和 SHA-256 替换为实际值：`training_config` 使用现有 Temporal BC 配置；`collector_bundle` 指向 `collection-prepare` 生成的独立环境，哈希绑定其中 `frozen.json`。路径相对调度配置文件。输出必须是新目录，并位于输入数据集和采集环境之外。工作区后续修改不会改变已经封存的数据清单。

## 调度规则

- CPU 训练使用实验配置指定的正整数 Torch 计算线程数，不额外设 2 线程上限；实际可运行范围仍受 Torch/主机接口约束。指定采集进程健康时可以并行。检查进程身份、版本核验、心跳和采样时间、图像年龄、归档积压及新增丢弃。配置、实际 worker 与录制 session 必须绑定同一冻结快照；分别通过哈希校验不等于三者一致。图像年龄取采样时的年龄；心跳发布延迟另行检查，不能把每秒发布一次状态误算成图像管线变慢。
- CUDA 采用交错基线：等待指定采集进程退出且正常释放/封存后，再按设备显存与利用率预算运行。不把暂停菜单或陈旧状态当作可用 GPU 时隙。其他 GPU 程序仍可能消耗资源；此机制不提供设备独占，也不证明实际游戏时效。
- 初始化、每次优化器更新、冻结和逐观测预测之间检查预算。压力出现时停止派发新工作，将模型/优化器张量移到 CPU，释放可回收的 CUDA 缓存；连续两次健康观测后恢复。CPU 张量仍保留，以便同一次运行继续相同优化器和随机序列。
- 本进程内存或磁盘余量越界、采集失败、单次工作超时、总时长或连续等待超限时停止。暂停/恢复的张量搬移也计入工作耗时；恢复返回后重新检查停止请求和预算，再决定能否派发下一步。调度是协作式的：正在执行的单个 Torch 操作不能由本模块强行抢占，超时在操作返回后记录并阻止下一步。它不能替代 #36 的独立动作到期机制。
- 资源查询在学习端进行并按 `poll_interval_s` 限频；采集热路径只更新现有状态字段。只投影准入所需字段、计数和摘要绑定，不把来源的任意诊断文本重复放入每个观察。缺失或无效的必要指标仍阻止准入。CPU 模式不调用 NVIDIA 资源查询。

调度预算的取值不再受第二套任意时间或容量上限限制。CPU 线程须为正整数，轮询间隔须为正数；
其他预算须为非负有限数值，GPU 利用率保留百分比的 0–100 定义域。数值必须来自实际容量、
测量或明确的实验预算，不能把示例当作本机已验证的限制。总时长为零时不启动工作；
等待预算为零时遇到资源压力直接停止、不睡眠。每次休眠取轮询间隔、剩余等待和剩余总时长的最小值，
避免较长轮询睡过实验预算；正在运行的单个 Torch 操作仍只能在返回后检查。
这一修改已通过配置/停止边界测试，超出旧门槛的实际训练测试尚待独立全量测试结束后执行。
状态不再因诊断内容超过 16 KiB 被拒绝；`frozen.json` 摘要校验按块读取，不再要求文件小于 4 MiB。
session、其他状态文件和候选清单读取的剩余限制仍列在资源审计中。

## 结果与停止

每次资源观察按行写入可选 `diagnostics/schedule-events.jsonl`，包括导致停止的最后一份指标。
`schedule.json` 的 `event_history` 保存路径、格式、行数、摘要和写入状态，替代旧内嵌 `events` 数组；
没有只留最后 1000 条的截断。展示历史时逐行读取此文件，不重新展开到主摘要。
日志打开、写入或刷新失败会标为 unavailable，并通过 `events_omitted` 显示缺口；
资源检查、停止请求和必要训练状态不依赖这份日志。未知诊断文本不进入此契约，错误的存在仍参与准入判断。

`schedule.json` 记录等待、压力原因、已完成及已持久化更新数、最长工作单元、输入配置和候选哈希。`requested-training.json` 保留原训练配置字节，`requested-schedule.json` 保留原调度参数；`training.json` 固定解析后的数据路径，`schedule-config.json` 绑定这份训练配置与解析后的采集路径。保留这些产物及数据依赖后，可在新输出目录重跑冻结配置，工作区原配置的修改不影响它。CPU 数值 BC 另可通过[完整 learner 检查点](bc-resume.md)继续剩余更新。完整训练和重载验证结束后，才把 `.candidate` 发布为 `candidate/`，其中仍是标准 BC 模型和联动画面报告；随报告发布的预览使用相对链接。停止时不发布候选，可能留下 `.candidate` 诊断文件；它不是 learner 检查点，也不证明可以续训。

CPU 恢复优先读取运行目录的 `learner/learner.json`，不要求 `schedule.json` 可读；训练和数据依赖仍须完整。只有没有发布新 learner 时，才通过调度报告定位仍有效的祖先检查点。`steps_completed` 与 `durable_steps_completed` 分别表示已计算和已封存更新，保存失败不得混同两者。调度报告写入发生 OS/内存错误时，返回摘要记录 `learning_schedule.schedule_report.status = unavailable`；已完成结果保持完成，`report_path` 指向已封存 learner。该错误状态只保证出现在返回摘要中。可选 loss 日志或累计统计缺失不阻止接续；不完整统计明确标记为 `partial`。

在输出目录创建 `stop.request` 可请求边界停止并保存 CPU learner。前台 Ctrl+C 也能停止，但不能保证保存正在执行的 Adam 更新；恢复以实际封存状态为准。完成返回码为 0，受预算或停止请求限制返回码为 2；输入损坏等错误保存诊断后报告异常。原始采集与输入数据不会因此删除或更改。

旧采集环境缺少 `last_poll_ns`、`latest_image_source_ns` 或 session 绑定时不能凭旧状态推断资源健康；应重新准备新的采集环境，保留旧录制。旧的 `temporal-train` 是不带采集协调的离线入口，采集期间应使用本入口。

已用合成输入验证压力暂停后与同种子普通训练预测一致；独立合成采集进程和真实 Windows 只读资源计数完成并行原型。CUDA 张量迁移与真实游戏负载仍需后续实测，不将 CPU 软件验证写成 GPU 性能结论。
