# 新管线后的分辨率选型与持续示范采集

2026-09-30 初版，实施状态更新于 2026-10-01。用户要求：新图像管线完成后，通过独立脚本持续记录本人多圈正常驾驶（包括起步），同时继续编码；大规模采集前先确定合适分辨率及缩放后的分布影响。本文保留实施要求和实验建议；[独立后台采集的软件切片](../guides/capture/continuous-collection.md)已实现并通过合成验证，真实 4K 选型与新多次人工驾驶采集仍未验收。本次状态更新没有启动游戏、采集或更改游戏设置。

## 1. 先区分三种分辨率

| 层级 | 含义 | 必须记录的条件 |
| --- | --- | --- |
| 游戏渲染 | 游戏内部生成场景所用的分辨率 | 菜单分辨率、渲染比例、动态分辨率／上采样与抗锯齿设置（若启用） |
| 采集源 | DXGI 桌面纹理与其中实际 FH5 客户区像素 | adapter／output、源纹理尺寸、物理像素裁剪框、窗口／显示模式、色彩路径 |
| 模型输入 | resize 后进入策略的数值图像 | 输出宽高、插值／抗混叠、颜色顺序、数值类型、归一化与处理版本 |

DXGI 提供桌面图像 surface，不能由游戏菜单分辨率推断源纹理或客户区尺寸。[Microsoft Desktop Duplication](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api)

本项目此前菜单显示 1920×1080 时，实测客户区曾为 3840×2160；后来的窗口采集实测为 1600×900，尚不能称已验证 1920×1080 客户区。见 [T08 记录](../validation/t08-policy-driving.md)。降低内部渲染分辨率但仍在 4K 桌面全屏输出，也不保证减少 DXGI 源纹理的数据量。

## 2. 同样 resize 不保证同样输入分布

`resize(render_at_4k(scene), 480×270)` 不保证等于 `resize(render_at_1080p(scene), 480×270)`。几何视野相同时，主要道路位置可以接近，但细小边缘、纹理、抗锯齿、锐化和 HUD 栅格化可能不同；若启用动态分辨率或时域上采样，还要检查运动中的变化。这里是采样与渲染机制的工程推断，不是 FH5 已测得的差异大小。

- 采集、训练与部署始终使用同一固定处理链时，resize 本身是输入定义的一部分，不自动构成训练／部署分布偏移。
- 只用 4K 来源训练、改用 1080p 来源部署，即使输出尺寸相同，也可能发生偏移；是否显著影响驾驶必须测量。
- 同宽高比不等于同视野。固定相机档位、FOV／裁剪、窗口比例、HUD／导航、画质与颜色路径；不能同时更换这些条件后把全部差异归因于分辨率。
- 离线与在线须使用同一预处理契约。OpenCV 的 `INTER_AREA` 是适合缩小的候选；Torchvision tensor resize 的 bilinear／bicubic 抗混叠选项也会影响结果。不能把不同库与默认值的 resize 当作数值等价。[OpenCV resize](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)、[Torchvision Resize](https://docs.pytorch.org/vision/stable/generated/torchvision.transforms.Resize.html)

只把一张 4K 截图离线缩成 1080p，再缩到模型尺寸，可以检查重采样敏感性，不能替代真正的 1080p 游戏渲染对照。同位置的两次实机截图也不是逐像素完全相同的场景；需控制相机、天气与运动并承认残差。

## 3. 大规模采集前的最小对照

用户随后明确“优先 4K”。先完成 DXGI 数值采集与源时间接口，**优先采用实际 3840×2160 游戏客户区作为采集来源**，记录内部渲染／上采样设置；以 480×270 模型输入作初始基线，需要时对照 640×360。先验证 4K 的画面质量和实时性；1080p 留作瓶颈诊断或有证据支持的后备方案，不作为大规模采集前必做对照。该选择尚未实测，未修改游戏设置。

| 对照 | 目的 |
| --- | --- |
| 4K 来源，先输出 480×270，需要时用同一批图像对照 640×360 | 确定所需道路／导航细节与模型计算成本 |
| 仅当 4K 出现难以满足的资源或时效问题时，再对照实际 1080p 来源 | 定位开销并评估后备方案及分布变化 |

首轮不同时扫描更多尺寸。保持原车、原调校、既定蓝图与追尾远档位；静止可重复场景查看道路／导航边缘，实际驾驶短段覆盖起步、转弯与较快运动，记录速度差异。不同采集配置分别版本化。短测保留少量高分辨率数值原图供对照，不能无限保存全部 4K 原始帧。

评价指标包括：道路与导航在最终输入中的可辨性、游戏帧时间、采集／预处理延迟 P50/P95/P99、最新可用观测年龄、缺帧／跳过比例和资源峰值。管线和模型可用后再测源帧到动作候选／发送的时效。只有像素、特征或预测动作差异不能证明驾驶优劣；现有 BC 尚未可靠起步，它对分辨率的敏感性只能作诊断。

4K 的源像素数为 1080p 的 4 倍，但不能由此断言延迟、FPS 或总开销恰好相差 4 倍；DXGI 纹理大小、裁剪发生位置和 GPU 预处理路径都会影响成本。最终模型尺寸相同时，网络计算量基本由该最终尺寸决定。640×360 的像素数是 480×270 的约 1.78 倍，推理与存档代价仍需实测。

选择规则：4K 满足时效与资源预算时，依用户偏好保留 4K，不因与 1080p 的细节差异小就默认降档。若出现瓶颈，先按实测优化采集、预处理与旁路负担，再评估是否需要降低源分辨率。若问题来自最终输入太小，单独评估 640×360。选定后，采集、训练与部署保持同一 4K 来源及预处理契约；基线通过再开始多圈采集，首次驾驶验证后继续复核。

以后改变源分辨率、HUD、相机、预处理或输入尺寸时建立新数据／模型条件；可以有意识地混合分辨率训练并分组验证，但不能不标记地混入。已经只保存 480×270 的数据无法恢复丢失的高分辨率细节。原始参数和最终输入数值都须可追溯。

## 4. 独立持续采集脚本

- **一次启动、持续记录。** 脚本作为独立进程运行，不依赖聊天回合存活或逐段提示。被动记录 RGB 数值像素、真实时间、遥测和已标定的实体手柄输入，不连接虚拟手柄、不发送驾驶动作。提供明确的状态查询、停止方式及心跳。
- **保持既定条件。** 用户使用蓝图 105657219、原车原调校和固定相机正常驾驶。当前蓝图为一圈，多次完成后手动重开原蓝图即可持续积累；不为采集擅改赛事，也不等待自动重开功能。
- **不阻塞编码。** 采集固定代码、依赖和配置版本，不热加载开发目录、不在采集环境同步依赖。开发使用独立环境；测试不得争抢 UDP 端口、采集器或真实输入设备。普通编码、CPU 检查及已封存数据分析可以继续，重 GPU 任务须服从实测预算。同一游戏不同时进行人工驾驶和模型接管。
- **边采边封存。** 有界异步写入，完整块原子封存；训练读取固定的不可变数据清单，新记录进入下一版本。记录帧引用、时间、来源、设备及协议版本，不边写边改变同一训练集。归档拥塞可形成明确缺口，不能阻塞或无限耗内存。
- **边界与恢复。** 菜单、失焦、倒带、重开或设备断连切开前向片段，恢复后重新建立历史。对圈界与碰撞等无法可靠判断的事件标为待核验，不伪造自动识别。异常退出可恢复已封存数据，磁盘不足有界停止，不覆盖旧证据。
- **观察采集是否有效。** 展示有效驾驶时长、完整数据比例、已确认尝试、行为覆盖、缺口与磁盘余量；常规重开不要求返回聊天重新启动采集。

## 5. 何时数据足够

建议先以 **3–5 次完整正常跑圈**作为第一批检查点；这是工程建议，不是用户指定数量、最低开训配额或效果保证。第一份合格快照形成后就可以分析和训练，用户继续采集；不足则按缺口补充，而非无限重复相同路线和动作。

| 维度 | 就绪依据 |
| --- | --- |
| 质量 | 数值像素可回放，输入／遥测时间与归属可信；缺失、暂停、倒带、重开有边界；排除理由可查 |
| 覆盖 | 起步、左右转向、不同弯道／速度、松油和 LT 制动均有有效样本；按事件及独立尝试计数，不只数相邻帧 |
| 独立性 | 按完整尝试分训练／开发／最终留出；倒带和重开的强关联片段作为同一组，必要时整段 session 留出；同路线多圈不等于陌生道路泛化 |
| BC 可用 | 独立留出包含关键行为；真实短段能够起步、方向修正与减速，明确区分模型动作和监督器停止 |
| 自主学习可启动 | BC 之外还需可信奖励／任务边界、真实动作转移、有界重开／恢复及冻结评估；圈数不能替代这些条件 |

用户正常转向和使用 RT／LT，不要求无转向地反复踩油门。无需每圈追求极限最快；自然驾驶和少量针对缺口的示范即可。保留失误与恢复原始记录，按用途筛选：正常片段可作 BC，条件明确的状态转移可作动力学监督，Q 学习还需可信奖励和终止信息。不能把所有失误当优质模仿标签，也不因一次失误删除整圈其他正常片段。

常规采集无需逐帧人工标注，结束后只核对系统定位的必要疑点。多圈示范用于启动后续自主学习，不改变持续由 AI 自身经验改进的目标。历史短段票保留原验收。后续已发布 [#37 持续采集](https://github.com/supermassiveasshole/horizon5-autonomous-driving/issues/37) 与 [#38 数据集及新 BC](https://github.com/supermassiveasshole/horizon5-autonomous-driving/issues/38)，分辨率来源核验沿用 [#34](https://github.com/supermassiveasshole/horizon5-autonomous-driving/issues/34)；当前软件证据见[采集验证记录](../validation/t35-continuous-collection.md)，不能替代真实新示范和游戏内验收。
