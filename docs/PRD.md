# FH5 歌利亚自主驾驶与学习实验 PRD

版本：1.1（2026-09-29 多模态学习增量）。状态：需求与任务调整已确认，RGB 采集及像素感知评估已完成；尚无驾驶学习模型训练结果。增量契约见 [多模态学习规格](multimodal-learning-spec.md)。

本文依据 Q1–Q15 的用户回答，以及对自主学习、奖励投机的补充讨论整理。它定义要交付的能力和验收证据；算法选型、工程参数与未验证假设另行标明，不把技术方案视为已实现的效果。决策来源见 [范围记录](scope-decisions.md)，术语见 [CONTEXT](../CONTEXT.md)。

## 1. 产品目标

在用户当前电脑上构建一个能够驾驶 Forza Horizon 5 第六元素完成歌利亚、并从自身驾驶经验中自主改进的实验系统。监督和模仿可以帮助初始化；之后系统应自行完成采样、恢复、训练、评估和版本筛选，逐步提高速度、稳定性和平顺程度。

实际驾驶策略必须使用视觉，联合本车遥测与预录路线进行监督/模仿初始化，再通过 RL 改进。传统控制器作为并行基线、对照或恢复工具，不是离线学习的前置。项目最终需要 RL 实质参与完整歌利亚驾驶，接受组合控制；传统控制器单独完赛不能替代这一目标。性能挑战先超过用户通常有效表现，再挑战个人最佳。无对抗全程能力与自主学习闭环得到验证后，继续探索有对手完赛、超车和比赛名次；个人成绩挑战可继续推进，突破个人最佳不是进入对手阶段的硬门槛。更通用的游戏内驾驶留作后续方向。

七天是首轮探索窗口，按照可运行里程碑汇报实际成果。它不构成全程 RL 完赛、超过本人或取得比赛名次的日期承诺。人工与电脑时间按需要安排，用户接受适量录制、标注和纠错；常规训练不能长期依赖人工看守。

## 2. 固定条件与范围

| 项目 | 已确认的约束 |
|---|---|
| 游戏与首条路线 | FH5；第一版只验收官方歌利亚（The Goliath）路线与检查点 |
| 首车 | 用户的 2011 兰博基尼第六元素极限竞速特别版 X 999；沿用当前 `BEST FOR SESTOFE`（`IMG BIRD`）调校；证据与待核实项见 [T03 配置记录](validation/t03-event.md) |
| 观测 | 真实截图历史必须进入驾驶策略，联合本车遥测与预录路线；精确分割和米制道路不作为学习总前置，模型估计不直接当作评测真值 |
| 比较条件 | 人类、基线、BC 与 RL 使用同车、同调校、同辅助及相同赛事/环境配置 |
| 辅助 | 关闭自动转向和自动刹车；其余辅助及换挡方式沿用用户现有设置并固定 |
| 正式成绩 | 无人工驾驶接管、无倒带，按顺序完成赛事检查点并获得游戏完成确认 |
| 道路规则 | 允许正常赛道内合理切弯；偶发接触记录；持续蹭墙、复位提速或草地捷径不构成有效进步 |
| 版本选择 | 可靠版本用于默认驾驶；更快但不稳定的激进候选单独保留与训练，遵守相同合法性规则 |

范围分为三个递进阶段：

| 阶段 | 交付方向 | 边界 |
|---|---|---|
| A：无对抗主线 | 基础驾驶、自主学习闭环、RL 全程完赛、个人成绩挑战 | 当前实施重点；各能力分别验收，进展不等于全部目标已完成 |
| B：有对手完赛 | 加入车辆感知、跟踪、局部交互及受撞恢复，完成比赛 | 无对抗全程能力与自主学习闭环得到验证后探索，个人成绩挑战可继续；具体对手难度进入本阶段前确定 |
| C：竞争名次 | 主动超车、竞速策略、争取名次 | 在 B 基础上定义难度与名次门槛 |

跨路线泛化、多车辆适配和未录制道路驾驶属于后续方向。首版不要求纯视觉端到端驾驶，也不要求取消所有传统控制辅助。自动采样与策略优化是首版自主性的核心；接口故障和长期停滞仍可由工程诊断解决。

## 3. 用户使用流程

1. **准备与记录。** 核对车辆、辅助和赛事条件，同步采集截图、遥测及可信动作示范，复用独立历史参考轨迹；个人成绩另按有效性规则留存。
2. **观察基础驾驶。** 先查看多模态观测回放与离线 BC 预测，再在核验过的有限短段实跑，查看轨迹、命令及失败位置；传统基线可并行推进。
3. **启动自主学习。** 初始化完成后，系统循环采样、恢复、更新、评估与保存；用户不必逐轮提供动作标签、重开或调整参数。
4. **查看进步。** 查看当前模式、训练是否推进、各版本的全部尝试、有效用时、失败类型及典型录像，分清自动运行成功与真实能力改善。
5. **执行正式验证。** 使用冻结策略关闭探索和倒带，在固定条件下检验全程能力，与基线、BC、旧策略及个人成绩比较。

用户随时可以停止运行；训练或调试中的人工救车可以记录，但会使该次尝试失去正式自主成绩资格。事后核查录像不属于驾驶接管，正常的自动训练循环不应要求每轮人工批准。

## 4. 功能需求

以下要求描述阶段 A 的目标能力，按里程碑逐步完成。尚未实现的功能不能在状态报告中标成通过。

| ID | 需求 | 可检查的验收证据 |
|---|---|---|
| FR-01 | 固定并记录实验配置 | 每次运行关联车辆、调校、辅助、赛事/环境、路线、策略和奖励/规则版本；配置变化另建比较批次 |
| FR-02 | 同步采集观测和实际命令 | 截图历史、遥测、可信动作、时间和控制权可回放；按决策时刻截断，区分原始输入、命令与游戏响应，能定位缺图、断流、延迟及状态跳变 |
| FR-03 | 建立道路与任务进度表示 | 参考轨迹、已核实走廊和检查点分别记录；标明未覆盖区域；路线匹配不凭空间接近跳过赛程 |
| FR-04 | 提供基础自动驾驶与对照 | 原车原调校完成低速标定，自动通过连续弯道并推进全程；失败可以定位与复现 |
| FR-05 | 从示范起步并通过 RL 改进 | 模仿约束可减弱并退出；策略可改变合法线路、转向及加减速；保留基线、冻结 BC 与在线 RL 的实际驾驶对照 |
| FR-06 | 自主运行学习循环 | 初始化后连续完成多轮采样、恢复/重开、更新、评估及保存，无逐轮人工示范、重开或调参；循环与异常都有日志 |
| FR-07 | 提供可控恢复与续训 | 正常救车、倒带恢复和完整重开区分记录；有限重试；可从保存的模型与训练状态恢复，不能只保存驾驶网络就宣称支持完整续训 |
| FR-08 | 防止已知奖励投机并检查成绩有效性 | 合法进度、违规、失败和倒带分段有明确逻辑；反例验证通过；确认违规不得被更快用时抵消，疑似结果隔离 |
| FR-09 | 自动筛选并保留两类版本 | 默认版本优先维持可靠性；激进候选展示合法最快成绩及失败情况；候选未通过评估不覆盖已验证版本 |
| FR-10 | 公平比较个人成绩与各策略 | 同条件保存通常有效用时中位数与个人最佳；展示全部尝试及失败，不仅展示成功最快的一次 |
| FR-11 | 展示可追溯的实验成果 | 可查看状态、轨迹、用时分布、失误位置、控制/速度变化和诊断录像；能追溯某次晋升的依据，界面形式由实现选择 |
| FR-12 | 正常停止并处理接口故障 | 用户停止、遥测过期或失去有效控制条件时按已验证流程解除输入、保存必要状态并停止或恢复；不无限重开或持续发送无效命令 |
| FR-13 | 视觉实际参与驾驶并独立评估作用 | 实际 actor 融合真实图像；分别报告视觉接入、利用及驾驶收益证据，保留无改善结果；仅录像或未使用的图像参数不能满足要求 |

## 5. 自主学习与恢复约定

自主循环为：采样 → 必要的恢复 → 策略更新 → 冻结候选评估 → 晋升或保留旧版 → 继续采样。训练候选可以暂时退步；没有通过筛选不意味着必须立即丢弃其全部学习进度。训练停滞应显示证据与原因线索，不能由训练轮数推断进步。

初期使用监督/模仿初始化，后续主要通过自身成功、失败和恢复经验学习。参考轨迹提供路线信息，不能被当作唯一正确赛车线；传统控制器的小幅动作修正不能成为策略永久上限。

自主倒带既是需探索的恢复能力，也是可选的训练重试工具。优先用规则监督器实现可靠操作，后续再探索学习何时倒带及退多远。其可用模式和效果须实测；若倒带不可用，采用已验证的完整重开继续工作，并把倒带能力记录为未实现或受当前模式限制，不能用重开替代其验收。

倒带前的失败必须保留，动画不进入普通驾驶经验，恢复后开启新的前向片段。短段成功、恢复后到达终点与无倒带全程完赛分开统计，多次重试的进度不能拼成完整成绩。

## 6. 奖励与有效性要求

训练目标是合法完成任务并改善驾驶，而非单纯增大车速读数。进度须与路线连续性、道路走廊和检查点顺序一致；同一前向片段不得靠往返重复领取新增进度奖励。时间、完成和失败回报一起设计，防止故意早撞以节省时间扣分，或通过停车、绕圈拖延获利。

正式成绩先检查有效性，再比较性能。持续蹭墙、复位提速和倒带不能被更快用时抵消，可靠默认版本和激进候选采用相同规则。允许偶发接触，避免把压路肩、急减速或侧滑直接等同于持续蹭墙。

规则检查必须报告覆盖范围与不确定性。确认违规结果无效，疑似违规暂不自动晋升并保存证据，正常循环无需人工逐轮盯守。不能声称本车遥测提供完整碰撞、道路或检查点信息，也不能承诺彻底消除未知投机。

实现前后的反例验证至少覆盖：高速离路/漏点、往返刷进度、路线定位跳跃、持续蹭墙、偶发接触、反复倒带、早撞/拖延及接口跳变。规则变更要版本化，并重评受影响成绩、重算或隔离相关训练标签。详细机制见 [奖励与有效性设计](reward-and-validity-design.md)。

## 7. 验收与指标

### 7.1 三类证据分别成立

| 验收对象 | 必须有的证据 | 不足以替代的现象 |
|---|---|---|
| 自主学习循环 | 无逐轮人工操作，完成预先定义的连续多轮采样、训练、评估与保存，异常可控 | 程序持续运行、一直驾驶同一个固定策略 |
| RL 驾驶改善 | 在线学习版本在固定条件的重复驾驶中，相比冻结 BC、基线或旧版本出现可重复的目标指标改善，并披露取舍 | loss 降低、训练回报上升、一次偶然最快记录 |
| RL 全程完赛 | RL 实质参与完整歌利亚，游戏确认完成；无人驾驶接管、无倒带；完整尝试与有效性证据可追溯 | 基线独自完赛、拼接多个成功短段、倒带后到达终点 |

这三类证据不能互相替代。只完成其中一项时报告该项进展；第一条有效全程是能力里程碑，可靠性仍需重复评估。个人成绩挑战继续在该基础上推进，不承诺固定训练量后必然达到。

### 7.2 比较指标与判定顺序

- **全量结果：** 有效完成、驾驶失败、确认违规、待核验、接口异常分别计数，并保留全部尝试及分类依据。
- **可靠性：** 报告评测批次大小和有效完成比例。驾驶失败及确认违规不能从比较中删除；待核验与接口异常单列，明确分母，不将接口故障直接归因于驾驶策略。
- **速度：** 比较有效完赛用时的中位数、分布和最佳值。先挑战个人通常表现，再挑战个人最佳；最低有效用时不代表整体可靠性更好。
- **稳定与平顺：** 报告失控/离路事件、正常恢复、接触以及无效方向振荡、踏板抖动。具体计算方法在标定后固定，不以一味柔和操作压制必要的快速控制。
- **控制贡献：** 报告 RL、传统控制器与恢复模块的控制区间和回退比例，并用对照检验学习贡献。组合控制成绩有效，但不能掩盖 RL 尚不能处理的路段；不额外要求 RL 独立输出全程每个动作。
- **训练与恢复成本：** 报告有效采样量、真实采样时长、重试、倒带和异常，辅助判断停滞与效率；不将恢复后的进度累计成正式成绩。

候选晋升先满足有效性规则，再执行可靠性和性能门槛。自动筛选前必须生成固定的评测协议，明确场景、重复次数、改进门槛、可靠性容差、异常处理与独立最终验收批次；协议未固定或证据不足时不自动替换默认版本。这些工程数值由实现者根据标定与基线制定，不能追认为用户已承诺的数字，也不能看到结果后临时降低门槛。

### 7.3 视觉接入、利用与收益

真实图像进入驾驶策略是主线要求。离线固定遥测/路线后改变图像，可以诊断策略是否利用视觉，但不能证明利用正确。驾驶收益需与合格的路线+遥测对照在同条件下重复实跑；仅向多模态网络喂黑图后表现下降不足以证明收益。完整视觉对照可与首次 SAC 并行，尚未证明的收益不得写成已实现。缺图回退及控制归属明确记录，不把退化为无视觉驾驶的区间称为完整多模态完成。

## 8. 里程碑与交付物

以下为成果依赖，不是按天排期。因果观测、同步示范与离线 BC 可先完成；不等待传统控制器、精确分割、全程走廊或自动重开。实机短段另需局部核验与控制验证，自动重复评估及 SAC 采样前需通过重开验收。

| 里程碑 | 可见交付物 | 进入下一步的依据 |
|---|---|---|
| M0 接口闭环 | 配置快照、同步观测/动作、轨迹回放、输入与重开诊断 | 真实输入、时间对齐与状态识别可信；能处理断流及停止 |
| M1 基础驾驶 | 因果观测与可信动作回放、离线多模态 BC 预测，再到短段实际驾驶 | 离线初始化和闭环驾驶分别验收；传统基线与全程覆盖并行完善 |
| M2 首次学习闭环 | BC 与 SAC 候选的短段驾驶对照 | 能采样、更新和评测；如实报告改善或无改善 |
| M2a 自主迭代 | 连续训练循环、恢复记录、版本筛选与续训证据 | 自动化是否成立、驾驶是否改善分别验证 |
| M3 RL 全程完赛 | 无人工接管、无倒带的完整有效运行及全部评估尝试 | 游戏完成确认、RL 控制贡献与成绩有效性通过检查 |
| M4 个人成绩挑战 | 同条件的人类/基线/BC/RL 用时与可靠性报告 | 先超过个人通常表现并保持可靠，再挑战最佳成绩 |
| M5 对手交互 | 有对手完赛，再探索超车与名次 | 无对抗全程能力与自主学习闭环得到验证；进入时确定难度和名次指标，验证感知与交互；不要求先完成 M4 个人最佳挑战 |

自主倒带在 M1–M2 期间并行探索，单独报告可用性与恢复效果。首轮七天结束时交付已实现版本、完整实验报告和下一步瓶颈，即使尚未完成全部里程碑也不虚报成功。

## 9. 技术主线与实现约束

当前主线：截图历史 + 本车遥测 + 独立历史参考路线 → 可信同步示范 → 多模态 BC 初始化 → 有界实机驾驶与重复评估 → SAC 在线学习及版本筛选。动作优先采用转向与有符号加减速，保持动作语义及数据版本清晰。BC→SAC 是当前工程选择，不是禁止后续更换方法的产品要求；变化必须保留需求、证据与公平对照。具体设计见 [驾驶学习主方案](driving-learning-design.md)与[多模态规格](multimodal-learning-spec.md)。

视觉编码器允许继续训练；经验保存原图/历史引用和预处理版本，以便表征更新后重算。未来轨迹可作监督标签，不能进入当时策略输入。移除分割前置不放宽合法进度、控制验证或正式成绩规则；局部未知仍保持未知。

本机已核实 i9-13900KF、约 64 GiB RAM、RTX 4090 24 GB，并已安装 Steam 版 FH5；这是硬件和安装事实，不是游戏与训练并行时的性能实测。数据及环境优先放在工作盘，日志/录像缓存应有容量上限，保留正式评估证据与已验证模型。[硬件记录](hardware-snapshot.json)

控制频率、时序容差、模型大小、采样与训练调度、恢复重试上限均由实现阶段标定。系统需要保持驾驶控制响应，防止训练阻塞游戏接口。保存模型、必要训练状态、配置与数据版本，以支持复现及中断恢复；复现不意味着游戏轨迹逐帧确定。

不假设存在任意位置状态重置、模拟时间加速或多个并行 FH5 实例。课程调度只能选择真实可到达、可重开的场景；若没有短段重试条件，采用完整重开、已支持短赛事或全程采样中的片段学习，正式验收仍回到歌利亚。

## 10. 待验证事实与失败分支

以下是工程验证任务，不是尚未达成共识的用户偏好。无需为这些事实继续发起范围问卷。

| 验证项 | 所需证据 | 不成立时的处理 |
|---|---|---|
| 遥测与输入接入 | 数据包、时间/坐标标定、游戏接收输入及输入释放记录 | 排查接口或替换适配实现；接入未通过不启动持续驾驶采样 |
| 空场歌利亚与固定条件 | 目标赛事可用、无其他车辆干扰、配置可记录 | 查明可用配置；若必须改动已确认赛事或比较目标，届时说明影响再对齐 |
| 道路、检查点和完成识别 | 标注/画面/状态与真实行驶相互验证 | 在已核实区域开展实验，补齐覆盖；不声称未知区域通过正式验收 |
| 重开与倒带 | 多次恢复操作、恢复后状态验证、失败退出记录 | 倒带不可用则完整重开；重开也未验证时暂不声称可无人值守训练 |
| 规则识别与误报 | 正常切弯、偶发接触、持续蹭墙及定位异常等验证片段 | 隔离不确定结果，改进观测/规则；不按未经确认成绩晋升 |
| RL 能否实际改善 | 固定条件下重复对照与完整失败记录 | 保留已验证版本，诊断数据、奖励、探索或算法；如实报告停滞 |
| 运行性能 | 游戏、采样、训练共存时的延迟与资源记录 | 调整频率、训练调度及采集负担；不将硬件容量当作实时性保证 |

目前没有需要用户再选择的首版范围事项。后续若事实导致必须更改赛程、车辆、成绩规则或阶段目标，再就具体影响讨论；常规实现调整由项目推进中解决。
